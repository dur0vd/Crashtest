# AGENTS.md — правила для Codex и других агентов

Crashtest — симулятор дорожных ситуаций с разбором по ПДД РФ, КоАП РФ и УК РФ.
TypeScript без фреймворков, Vite, тесты на vitest, мобильная сборка через Capacitor.
Цель развития проекта — инструмент реконструкции ДТП, пригодный для работы аварийного
комиссара и как вспомогательное средство автотехнического эксперта. План работ лежит в `docs/codex/`.

## Команды

```bash
npm ci
npm test           # vitest: геометрия, симуляция, разбор, целостность базы норм
npm run typecheck  # tsc --noEmit
npm run build      # проверка типов + сборка в dist/
```

Перед тем как считать задачу выполненной, должны проходить `npm test` и `npm run build`.

## Устройство

- `src/geom.ts` — векторы, OBB/SAT, сплайны; `src/scene.ts` — модель сцены и каталог ТС;
  `src/geo.ts` — производная геометрия дорог; `src/sim.ts` — детерминированная симуляция (таймлайн кадров, DT = 0.025 с);
- `src/law.ts` — краткий справочник норм; `src/corpus.ts` + `src/data/*.json` — полный корпус ПДД, КоАП гл. 12, УК гл. 27;
- `src/restrictions.ts` — знаки, разметка, грузы; `src/analysis.ts` — разбор: нарушения, причинная связь, техвозможность, квалификация;
- `src/presets.ts` — готовые сценарии (они же тестовые); `src/render.ts`, `src/editor.ts`, `src/ui.ts`, `src/main.ts` — интерфейс.
- Симуляция и разбор — чистые функции от сцены без доступа к DOM. Так и должно оставаться.

## Правила

1. **Нормы права.** Не выдумывай номера пунктов, частей статей и размеры санкций. Всё, что попадает в `law.ts`
   или `src/data/*.json`, сверяй с официальным текстом (pravo.gov.ru, consultant.ru). Если проверить не можешь,
   оставь `TODO(legal-check)` с указанием, что именно надо проверить, и не выдавай значение за точное.
2. **Физика.** Каждая формула должна иметь комментарий с источником (учебник, методика, статья) и единицами измерения.
   Константы — именованные, с единицами в имени или комментарии (`REACT_S`, `DECEL_MS2`).
3. **Детерминизм.** Одна и та же сцена должна давать побитово тот же результат. Без `Math.random()` в движке;
   для Монте-Карло — сидируемый ГПСЧ, сид сохраняется в отчёт.
4. **Техническое отдельно от правового.** Расчёт (скорости, пути, время, возможность предотвратить) и правовая
   оценка (нарушение, состав, санкция) — разные слои и разные разделы отчёта. Движок не «назначает виновного»:
   вину устанавливает суд, а программа даёт технические выводы и ориентировочную правовую квалификацию.
5. **Тесты.** Новая логика сопровождается тестом. Для физики — сравнение с аналитическим решением с допуском;
   для разбора — сценарий в `presets.ts` или в тесте и проверка ссылок на нормы.
6. **Совместимость сцен.** Формат сцены версионирован; старые сохранённые файлы и ссылки должны открываться
   (миграция в `scene.ts`).
7. Комментарии и тексты интерфейса — на русском, в стиле существующего кода.
