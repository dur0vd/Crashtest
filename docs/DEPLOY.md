# Сервер и домен

Crashtest — статический сайт (PWA) с отдельным API. Приложение проверяет коды активации офлайн. API обслуживает облачные сцены и может принимать оплату личной подписки через Т-Банк.

## Что нужно сейчас

| | Требование |
| --- | --- |
| Сервер | Любой VPS в России: 1 vCPU, 1 ГБ RAM, 10 ГБ SSD, Ubuntu 24.04 LTS (Timeweb Cloud, Selectel, REG.RU, Yandex Cloud). Обычно 200–400 ₽ в месяц. |
| Почему в России | Персональные данные покупателей подписки (почта, реквизиты школ) должны храниться в РФ (ч. 5 ст. 18 Закона № 152-ФЗ). Сайт с российским IP стабильно открывается у школ. |
| Домен | Зона `.ru`, коротко и без дефисов (например `crashtest.ru`). A-запись `@` → IP сервера, `www` → CNAME на основной домен. Включите автопродление. |
| HTTPS | Обязателен: без него не работают офлайн-режим и установка на домашний экран. Бесплатный сертификат Let's Encrypt (`certbot`). |
| Веб-сервер | nginx; конфиг `deploy/nginx.conf` ставит `deploy/setup-server.sh` (кэширование, заголовки безопасности, журналы без IP-адресов). |
| Выкладка | GitHub Actions `deploy-server.yml`: при каждом слиянии в `main` настраивает сервер, собирает, тестирует и копирует сборку по SSH, хранит 5 версий для отката. |

## roadpdd.ru: запуск

Сервер `45.132.176.226`, пользователь `user1`, сайт в `/var/www/roadpdd`. Сервер настраивает GitHub Actions (`deploy-server.yml` и скрипт `deploy/setup-server.sh`): nginx, сертификат Let's Encrypt, HTTPS, выкладка сборки. Вручную на сервер заходить не нужно.

1. **DNS.** У регистратора домена создайте A-записи `roadpdd.ru` → `45.132.176.226` и `www.roadpdd.ru` → `45.132.176.226`. Если домен куплен недавно, дождитесь делегирования (до суток).
2. **sudo без пароля для `user1`.** Один раз на сервере под root: `echo 'user1 ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/user1 && chmod 440 /etc/sudoers.d/user1`. Если `user1` уже root, шаг не нужен.
3. **Ключ в GitHub.** Settings → Secrets and variables → Actions → New repository secret, имя `DEPLOY_KEY`, значение — закрытый SSH-ключ `user1` целиком, от `-----BEGIN` до `-----END`.
4. **Запуск.** Actions → Deploy to server → Run workflow. Дальше каждое слияние в `main` выкладывается само.

Пока DNS не указывает на сервер, сайт открывается по `http://45.132.176.226`. Сертификат и HTTPS включатся сами при первой выкладке после того, как A-запись заработает. Повторить выкладку можно кнопкой Run workflow.

Откат: на сервере `ls /var/www/roadpdd/releases`, затем `ln -sfn /var/www/roadpdd/releases/<версия> /var/www/roadpdd/current`.

Безопасность: ключ, который пересылался в переписке, лучше заменить отдельным ключом только для выкладки. На своём компьютере выполните `ssh-keygen -t ed25519 -f roadpdd-deploy`. Добавьте `roadpdd-deploy.pub` в `~user1/.ssh/authorized_keys`, закрытый ключ запишите в `DEPLOY_KEY`, а старый ключ удалите из `authorized_keys`.

## API облачных сцен

Каталог `server/` собирается в один файл (`npm run build:server` → `dist-server/index.js`). `deploy/setup-server.sh` ставит Node 22 и `sqlite3`, создаёт systemd-юнит `crashtest-api` (порт 8787 только на localhost), каталог данных `<сайт>/data` и ежедневную копию базы в `data/backups` (хранится 14 дней); nginx проксирует `/api/` на тот же origin. Workflow `deploy-server.yml` копирует `dist-server/` в `<сайт>/api/` и перезапускает юнит.

Настройки — в `<сайт>/data/api.env` (формат `KEY=value`):
- `SMTP_HOST`, `SMTP_PORT` (по умолчанию 465, неявный TLS; 587 — STARTTLS), `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` — отправка кодов входа напрямую по SMTP. Для Яндекса и Mail.ru создайте пароль приложения (не основной пароль): `smtp.yandex.ru` / `smtp.mail.ru`, порт 465. Без шифрования сервер не входит;
- `MAIL_WEBHOOK_URL` — запасной вариант: HTTP-шлюз (POST JSON `{to, subject, text}`), используется, если `SMTP_HOST` не задан; без обоих код входа только печатается в журнал `journalctl -u crashtest-api`;
Файл должен быть доступен только `user1` (`chmod 600 api.env`); после правки: `sudo systemctl restart crashtest-api`;
- `ALLOW_ORIGIN` — разрешённый Origin для CORS, нужен приложениям Capacitor и сайту на GitHub Pages (для них при сборке задаётся `VITE_API_URL`).

Перед запуском для пользователей: уведомление Роскомнадзора об обработке персональных данных (почта), проверка текста `docs/legal/privacy.md`.

## Оплата личной подписки через Т-Банк

Оплата за 30 дней проходит на форме Т-Банка. Код активации отправляется после `CONFIRMED`. При сбое доставки сервер повторяет отправку того же кода. Автошкола запрашивает счёт по почте. По умолчанию онлайн-оплата выключена.

1. Настройте одностадийную оплату, кассу и HTTP(S)-уведомления в личном кабинете интернет-эквайринга. Для первых проверок используйте терминал `DEMO` на отдельном тестовом сайте с HTTPS. [Настройки терминала](https://developer.tbank.ru/eacq/intro/developer/terminal) · [Тест-кейсы Т-Банка](https://developer.tbank.ru/eacq/intro/errors/test-cases)
2. Поместите закрытый ключ кодов активации на сервер вне репозитория, например в `/var/www/roadpdd/data/license-private.pem`. Установите права `600` и убедитесь, что ключ читается пользователем API. Его открытый ключ должен входить в `src/license-keys.json`. Если нужен новый ключ, выпустите его через `node tools/issue-code.mjs init` и включите открытый ключ в сборку приложения.
3. Настройте доставку писем через SMTP или `MAIL_WEBHOOK_URL` и заполните параметры в `data/api.env`. Используйте значения системы налогообложения, ставки НДС и предмета расчёта, согласованные для вашей кассы. [Поля чека в Init](https://developer.tbank.ru/eacq/api/init)

   | Переменная | Значение |
   | --- | --- |
   | `TBANK_TERMINAL_KEY` | Идентификатор терминала из кабинета Т-Банка |
   | `TBANK_PASSWORD` | Пароль этого терминала |
   | `CRASHTEST_KEY` | Абсолютный путь к закрытому ключу кодов |
   | `TBANK_SITE_URL` | HTTPS-адрес сайта для уведомлений и возврата покупателя. По умолчанию `https://roadpdd.ru` |
   | `TBANK_RECEIPT_FFD` | Версия ФФД терминала, `1.05` или `1.2` |
   | `TBANK_RECEIPT_TAXATION` | Значение `Receipt.Taxation` |
   | `TBANK_RECEIPT_TAX` | Значение `Receipt.Items[].Tax` |
   | `TBANK_RECEIPT_PAYMENT_OBJECT` | Значение `Receipt.Items[].PaymentObject` |
   | `TBANK_ENABLED` | `true` для включения |

4. Перезапустите `crashtest-api`. Проверьте, что `GET /api/payments/config` возвращает `{"available":true}`. Адрес уведомлений формируется как `<адрес сайта>/api/payments/tbank`. Оба исхода возвращают покупателя на страницу статуса, которая запрашивает состояние платежа у сервера.
5. Проверьте на DEMO-терминале успешную оплату, отмену и доставку кода. Проверьте отдельно формирование и отправку чека кассой. Перед включением рабочего терминала заполните реквизиты правообладателя в публичных документах и обновите параметры терминала и сайта. Возвраты оформляются в личном кабинете эквайринга. Уже выданные офлайн-коды действуют до своего срока окончания. [Возвраты Т-Банка](https://developer.tbank.ru/eacq/scenarios/cancel_confirm/)
