Сейчас удар в Crashtest — поступательный обмен импульсом по нормали (src/sim.ts, Collision

2. Энергия деформации: метод CRASH3 (коэффициенты жёсткости A, B по классам ТС) — по профилю деформации

3. Многократные удары (вторичные столкновения, удар о препятствие после первого), контакт с бордюром и
   отбойником.
4. Послеударное движение: качение/скольжение с заблокированными или свободными колёсами, вращение,
   остановка в конечном положении. Конечное положение должно совпадать с наблюдаемым — это основа
   обратной задачи (этап 12).
5. Отчёт столкновения: Δv, PDOF, EES, k, μc, угол рыскания после удара, путь отброса — в technical-разделе.
6. Оценка вреда (src/analysis — harmFor) переходит на Δv и PDOF с вероятностными кривыми (риск травмы

   категория; категории тяжести вреда (лёгкий/средний/тяжкий) — только как ориентир с оговоркой, что их

7. Тесты: сохранение импульса и момента импульса; k = 0 и k = 1 — предельные случаи; центральный удар
   совпадает с аналитическим; энергетический баланс (кинетическая до = после + деформация + трение).

==== Этап 10. Параметры экспертных расчётов, видимость, обзорность, ночь ====

В Crashtest остановочный путь считается как S = v·(t1 + t2) + v²/(2a) с фиксированными
t1 = 1,0 с и t2 = 0,2 с (techFor в src/analysis.ts; docs/LEGAL.md). В отечественной автотехнической
экспертизе используется формула с временем нарастания замедления:
S = v·(t1 + t2 + 0,5·t3) + v²/(2·j), где t1 — время реакции водителя, t2 — запаздывание тормозного привода,
t3 — нарастание замедления, j — установившееся замедление.

1. Вынеси параметры в src/expert/params.ts с таблицами и источниками:
   - t1 — по типу дорожной ситуации (опасность в поле зрения заранее / внезапно, необходимость оценки);
     значения бери из методических рекомендаций по производству автотехнических экспертиз
     (TODO(legal-check): укажи точное название и год источника, значения не выдумывай);
   - t2, t3 — по типу тормозного привода (гидравлический/пневматический) и категории ТС;
   - j — по покрытию, состоянию, категории ТС и нагрузке; нормативы эффективности тормозов из
     ГОСТ 33997-2016 как нижняя граница исправного ТС.
   Пользователь может переопределить любой параметр, и это фиксируется в отчёте как отступление от таблицы.
2. Все расчёты техвозможности считать для диапазона параметров (минимум, максимум, типовое) — вывод
   «мог / не мог / зависит от параметров (граница при t1 = …)».
3. Видимость и обзорность: время суток, освещение (фонари, фары ближнего/дальнего, ослепление),
   туман/осадки как дальность видимости; препятствия обзору (здания, стоящие ТС, стойки кузова) — расчёт
   линии видимости в 2D и момента, когда участник мог быть обнаружен. Это заменяет константу «видимость
   100 м».
4. Момент возникновения опасности — по правилам экспертной практики (пешеход вступил на проезжую часть /
   в полосу ТС / изменил направление), с выбором варианта и пояснением в отчёте.
5. Жёлтый сигнал (п. 6.14): проверять возможность остановиться служебным торможением с учётом t1–t3,
   а не только v²/(2a).
6. Обнови docs/LEGAL.md (раздел про техническую возможность).
7. Тесты: ручной пример расчёта из выбранной методики воспроизводится до сантиметра.

   расстоянием, прозрачность. Импорт геометрии дорог из OpenStreetMap (по координатам) — опционально,
   с атрибуцией OSM.
4. Фото с места: прикрепление к объектам, хранение оригинала с EXIF и хэшем (подготовка к этапу 15).
5. Валидация ввода: противоречия (след длиннее, чем позволяет скорость; конечное положение за
   препятствием) — предупреждения.
6. Экспорт масштабной схемы ДТП в PDF/SVG в виде, близком к принятому оформлению схемы места ДТП
   (условные обозначения, масштаб, ориентиры, подписи понятых/участников как пустые поля).

==== Этап 12. Обратная задача и неопределённость (Монте-Карло) ====

Сейчас Crashtest решает прямую задачу: пользователь задаёт скорости — программа
показывает исход. Эксперту нужна обратная: по следам и конечным положениям (этап 11) найти скорости
и траектории, и честно показать разброс.

1. Классические формулы реконструкции как отдельные калькуляторы в src/expert/calc/*.ts, с источниками и
   выводом промежуточных значений: скорость по длине тормозного следа (с учётом t3), по боковому скольжению,
   по критической скорости на дуге, по отбросу пешехода (этап 09), по закону сохранения импульса
   (двумерная диаграмма импульсов), по EES (этап 08).
2. Оптимизатор: неизвестные (скорости до удара, точка и угол удара, k, μ) подбираются так, чтобы
   смоделированные следы и конечные положения совпали с наблюдаемыми. Функция невязки — взвешенная по
   заявленной погрешности измерений. Метод — Нелдер–Мид или дифференциальная эволюция, детерминированный
   по сиду. Результат — лучшее решение + невязка по каждому наблюдению.
3. Монте-Карло: входные параметры задаются распределениями (равномерное/нормальное/треугольное с
   границами), N прогонов (по умолчанию 1000) в Web Worker, сидируемый ГПСЧ. Выход — диапазон
   (5–95 перцентиль) для каждой искомой величины и для вывода о технической возможности
   («в 87 % прогонов остановиться было возможно»).
4. Анализ чувствительности: какие входные параметры сильнее всего влияют на вывод (tornado-диаграмма).
5. UI: панель «Реконструкция» с исходными данными, ограничениями, ходом расчёта, графиками распределений.
6. Тесты: синтетическая сцена с известными скоростями → «следы» → обратная задача восстанавливает
   скорости в пределах погрешности; одинаковый сид → одинаковый результат.

==== Этап 13. Анализ видео: скорость и положение по кадрам ====

Самое частое объективное доказательство в спорах о ДТП — запись видеорегистратора или
камеры наблюдения. Добавь в Crashtest модуль покадрового анализа (всё в браузере, видео не уходит на сервер).

1. Загрузка видео, покадровая навигация, извлечение реальной частоты кадров и меток времени кадров
   (переменный FPS — частая ошибка; предупреждать, если метки неравномерны). Хэш исходного файла.
2. Калибровка неподвижной камеры: гомография «изображение → план дороги» по ≥ 4 точкам с известными
   координатами из сцены (разметка, углы перехода, опоры). Показать погрешность репроекции.
3. Разметка объекта на кадрах (ручная, точка контакта колеса с дорогой); расчёт положения на плане,
   скорости и ускорения со сглаживанием и доверительным интервалом с учётом погрешности клика и
   калибровки.
4. Камера в движущемся ТС (регистратор): скорость носителя по прохождению известных отметок (штрихи
   прерывистой разметки 1.5 известной длины, опоры), момент появления опасности в кадре.
5. Синхронизация видео с таймлайном симуляции и светофорным циклом; наложение смоделированных
   положений на кадр для визуальной проверки.
6. Результаты — наблюдения для обратной задачи (этап 12) с погрешностью.
7. Тесты: синтетическое «видео» (сгенерированные проекции известного движения) → модуль восстанавливает
   скорость в пределах заданной погрешности.

==== Этап 14. Отчёт в структуре заключения эксперта/специалиста ====

Нужен экспорт результатов Crashtest в документ, который эксперт или специалист может
положить в основу своего заключения, а аварийный комиссар — приложить к материалам. Используй разделы
отчёта technical / rules / legal и trace из задачи 03.

1. Генерация PDF в браузере (pdf-lib или аналог, шрифт с кириллицей встроить) и DOCX (для правки).
2. Структура (ориентир — требования к содержанию заключения в ст. 25 ФЗ «О государственной судебно-
   экспертной деятельности в РФ» и ст. 204 УПК РФ; TODO(legal-check) сверить перечень):
   - вводная часть: кто, когда, по чьему запросу, поставленные вопросы (поле ввода вопросов
     «Какова скорость…», «Имел ли водитель техническую возможность…»);
   - исходные данные: перечень материалов (схема, протокол осмотра, видео, фото) с хэшами;
     принятые исходные данные с источниками и погрешностями;
   - исследование: методы, формулы с подстановкой чисел, промежуточные результаты, графики, схемы на
     ключевые моменты, результаты Монте-Карло и чувствительности;
   - выводы: ответы на каждый вопрос, категоричные или вероятностные — в зависимости от разброса;
   - отдельный раздел «Соответствие действий участников ПДД (с технической точки зрения)»;
   - правовая оценка — только в режиме «аварийный комиссар / учебный», в экспертном режиме по умолчанию
     выключена (эксперт не решает правовые вопросы);
   - приложения: параметры, версия программы, хэш сцены, журнал изменений (этап 15).
3. Шаблоны отчёта: «Справка аварийного комиссара», «Расчёт для специалиста», «Учебный разбор».
4. Тексты выводов — шаблонные, без оценочных формулировок («виновен»); проверка: в отчёте нет слова
   «виновен» и нет вывода без ссылки на расчёт.
5. Тест: снимок (snapshot) текстовой части отчёта для 3 пресетов; PDF открывается и содержит хэш сцены.

==== Этап 15. Воспроизводимость, журнал изменений, целостность ====

Чтобы расчёт Crashtest можно было проверить в суде, другая сторона должна получить тот же
результат из тех же данных, а любое изменение исходных данных должно быть видно.

1. Версионирование: SEMVER движка (физика + разбор) отдельно от UI; версия корпуса норм; всё — в каждом
   сохранённом файле и отчёте.
2. Формат проекта .crashtest (zip): scene.json (канонический JSON — отсортированные ключи, фиксированная
   точность чисел), вложения (фото, видео, сканы) как есть, manifest.json с SHA-256 каждого файла,
   журнал изменений.
3. Журнал: каждое действие редактора, меняющее исходные данные (не вид), записывается: время, что
   изменено, было/стало, кто (имя пользователя в настройках). Отмена/повтор тоже пишутся. Просмотр
   журнала и «откат к версии».
4. Пересчёт: команда «проверить воспроизводимость» — пересчитать сцену и сравнить с результатом,
   сохранённым в файле; при расхождении — показать, что отличается, и версию движка, в которой считали.
   Хранить старые версии движка невозможно в браузере — достаточно явного предупреждения и CLI.
5. CLI: `npx crashtest-verify project.crashtest` (Node, без DOM) — пересчитывает и печатает хэши и
   ключевые результаты. Добавь bin в package.json.
6. Детерминизм: тест, что результат одинаков в Node и в браузере (Chromium через playwright) — следи за
   Math.* функциями; при необходимости свои реализации sin/cos/exp с фиксированной точностью или
   округление на границах шагов.
7. Необязательно: электронная подпись отчёта (файл подписи рядом с PDF) — оставь точку расширения.

==== Этап 16. Режим аварийного комиссара (работа на месте ДТП) ====

Аварийный комиссар работает с телефона на месте ДТП, часто без связи, за 20–40 минут.
Сделай в Crashtest отдельный режим (переключатель в меню), оптимизированный под это. Мобильная сборка —
Capacitor (android/, ios/).

1. Мастер по шагам: дата/время/адрес (геолокация) → тип места (шаблоны: перекрёсток, Т-образный,
   кольцо, парковка, прямая) → участники (тип, госномер, полис ОСАГО — поля) → положение ТС
   (перетаскиванием на шаблоне) → следы и осыпь → повреждения (схема кузова, тап по зоне) → фото →
   пояснения участников (текст/диктовка) → предварительный разбор.
2. Фото с камеры: геометка, время, хэш, привязка к объекту схемы; обязательный набор ракурсов
   (общий план, номера, повреждения, положение относительно разметки) как чек-лист.
3. Измерения: ввод с рулетки/дальномера; опционально AR-измерение (ARCore/ARKit через плагин Capacitor) —
   с явной пометкой точности.
4. Европротокол (ст. 11.1 закона об ОСАГО): проверка условий оформления без полиции (число ТС,
   отсутствие вреда здоровью, лимиты, разногласия) по редакции на дату (задача 02); подсказка, какие
   поля бланка заполнить. Не имитировать официальные сервисы и бланки — только подсказки.
5. Предварительная оценка для ОСАГО: нарушения ПДД в причинной связи по каждому участнику; если
   определить невозможно — указать, что по закону об ОСАГО (п. 22 ст. 12) страховщик выплачивает в равных
   долях до установления вины судом (TODO(legal-check) сверить пункт). Степень вины в процентах
   не выдавать.
6. Офлайн: всё работает без сети, синхронизация/экспорт .crashtest (этап 15) позже.
7. Итог — «Справка аварийного комиссара» (шаблон из этапа 14).
8. UX: крупные элементы, работа одной рукой, тёмная тема на солнце — светлая высококонтрастная.

==== Этап 17. Верификация и валидация ====

Без опубликованной валидации расчёты Crashtest нельзя использовать как экспертный инструмент.
Сделай набор проверок и отчёт.

1. Верификация (код считает то, что заявлено): tests/verification/ — для каждой формулы из
   src/expert/calc и src/physics аналитический или опубликованный ручной пример с допуском; генерация
   таблицы «формула — источник — пример — результат — допуск — статус».
2. Валидация (модель согласуется с реальностью): tests/validation/ с данными из открытых источников —
   краш-тесты (например, открытые базы NHTSA: скорости, Δv, деформации), опубликованные натурные
   испытания торможения и наездов на манекены. Данные хранить в tests/validation/data/ с указанием
   источника и лицензии; не включать данные, лицензия которых запрещает распространение — тогда только
   скрипт загрузки.
   Метрики: ошибка по Δv, конечному положению, скорости по следу; целевые допуски задать константами
   и обосновать в документе.
3. Перекрёстная проверка: набор эталонных сцен, для которых результаты можно сравнить с другим
   программным обеспечением реконструкции, — формат описания сцены и таблица для внесения чужих
   результатов вручную (само чужое ПО не использовать и не копировать).
4. docs/VALIDATION.md, собираемый скриптом `npm run validation-report`: версия, дата, все таблицы,
   известные ограничения и области, где модель не валидирована (явно).
5. CI: GitHub Actions — npm test, build, верификация на каждый PR; валидация — по расписанию/вручную.

==== Этап 18. Персональные данные, хранение, безопасность ====

Как только в Crashtest появляются госномера, ФИО, полисы, фото и видео с места ДТП

2. «Поделиться по ссылке» (сейчас сцена кодируется в URL): в режимах комиссара/эксперта запретить для
   проектов с персональными данными или вырезать их с предупреждением.

   на фото (ручная разметка областей; автоматическое распознавание — опционально и локально).
5. Удаление: полное удаление проекта и вложений с устройства.
6. Документ docs/PRIVACY.md: какие данные, где хранятся, кто оператор (пользователь), шаблон согласия
   участников ДТП на обработку, рекомендации комиссару. Юридические формулировки — TODO(legal-check).
7. CSP в index.html, зависимость-аудит (npm audit) в CI.

==== Этап 19. Учебный режим для автошкол (по желанию) ====

Помимо экспертного применения Crashtest используют в автошколах. Сделай учебный режим.

1. «Угадай»: перед показом разбора задать вопросы — «Кто должен уступить?», «Какой пункт ПДД нарушен?»,
   «Мог ли водитель остановиться?» — варианты ответов генерируются из отчёта (правильный + правдоподобные
   неверные из того же раздела ПДД). После ответа — разбор с выделением ошибки.
2. Каталог сцен по темам экзаменационных билетов категорий AB (перекрёстки, обгон, переходы, остановка,
   переезды, спецтранспорт…), фильтр по теме и сложности.
3. Режим преподавателя: «проектор» — крупные знаки и подписи, пауза на ключевом моменте с вопросом
   классу, пошаговое воспроизведение; набор сцен в «урок» и ссылка на урок для учеников.
4. Вид от водителя (простой 3D или псевдо-3D) из точки водителя в момент возникновения опасности —
   показывает обзорность (этап 10).
5. Знаки на холсте при мелком масштабе не исчезают: минимальный экранный размер значка.
6. Шаблоны «Новая ситуация»: Т-образный перекрёсток, крестообразный, кольцо, двор, загородная дорога.
