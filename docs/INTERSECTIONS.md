# Проезд перекрёстков

Источник требований — раздел 13 и раздел 6 `src/data/pdd.json`.
Текст нормы в отчёте выбирается из датированного корпуса по дате ДТП;
геометрические и временные пороги распознавания не являются числами из ПДД.

## Геометрия и наблюдения

`buildGeo` формирует `intersections` и подходы дорог. Прилегающая территория
с `Road.role='adjacent'` исключается из определения перекрёстка. Связанные
примыкания кольца группируются. `classifyIntersectionMovement` использует
полный заданный маршрут, включая запланированный выезд после места контакта.

Автоматические границы — `automatic-estimate`: в модели нет обмеренных начал
закруглений из определения п. 1.2. Пользователь может задать измеренный контур
`Scene.intersectionBounds` (`survey`). Предполагается пересечение дорог в одном
уровне. Роль дороги и наличие покрытия должны соответствовать материалам дела;
старым сценам для совместимости назначается твёрдое покрытие.

## Сигналы и очерёдность

`traffic-control.ts` рассматривает основной сигнал со стрелками, дополнительную
секцию, мигающий жёлтый, отключение, реверсивные и трамвайные сигналы, статические
жесты регулировщика. Неизвестные исходные данные дают неопределённый результат.
Выключенный реверсивный сигнал сам по себе не доказывает запрет: для п. 6.7
нужно установить наличие разметки 1.9 с обеих сторон полосы.

`analysis/intersections.ts` строит граф `уступающий → имеющий преимущество`
для временных групп подъезжающих участников. Сильно связанный цикл не назначает
нарушителя; отчёт указывает необходимость согласования по п. 13.11 и 1.5.
Приоритет на круге учитывает исключение для главной дороги из п. 13.11(1).
Направления главной при 8.13 заданы абсолютными азимутами въездов.

Нарушение обязанности уступить требует наблюдаемой помехи; само наличие ребра
не является доказательством нарушения. Положительный вывод относится только
к наблюдавшемуся требованию, а не ко всем действиям участника.

ст. 12.18; запрещающего сигнала/жеста — ч. 1 ст. 12.12. Составы и санкции
проверяются по корпусу, с сохранением предупреждений о сроках редакций.

## Проверки

Парные сценарии охватывают каждый пункт 13.1–13.13, включая 13.11(1).
Дополнительные сценарии проверяют стрелки, трамвай, регулировщика и четыре
одновременных подъезда. Отдельные тесты проверяют геометрию, ручной контур,
сигналы, ссылки на части КоАП и сохранение остановки с паузой при перелёте
путевой точки. Синтетические сцены проверяют заявленное поведение кода;
они не заменяют валидацию реконструкции по натурным данным.
