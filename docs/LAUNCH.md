# Запуск roadpdd.ru, Роскомнадзор и уход с GitHub

Чек-лист владельца. То, что делается кодом, уже в репозитории; здесь — действия вне его.

## 1. Домен и сервер (cloud.ru)

1. У регистратора: A-записи `roadpdd.ru` и `www` → внешний IP ВМ. Проверка: `dig +short roadpdd.ru`. Если IP отличается от `45.132.176.226`, поправьте его в `deploy-server.yml` и `docs/DEPLOY.md`.
2. В cloud.ru: внешний IP привязан к ВМ, группа безопасности пускает входящие 22, 80 и 443 (80 нужен Let's Encrypt).
3. На ВМ: пользователь с `sudo` без пароля и отдельный SSH-ключ только для выкладки (`docs/DEPLOY.md`).
4. Запустить выкладку: `setup-server.sh` поставит nginx, сертификат, Node 22 и сервис `crashtest-api`.
5. Создать `/var/www/roadpdd/data/api.env` с `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` (см. `docs/DEPLOY.md`) и перезапустить `crashtest-api`. Без этого код входа не уходит на почту.
6. Проверить: `curl -I https://roadpdd.ru`, затем вход из браузера и письмо с кодом.

## 2. Роскомнадзор (152-ФЗ)

Почта пользователя при входе в облако — персональные данные, поэтому владелец сервиса — оператор. Что подготовить (юридическое заключение даёт юрист):

- Пакет документов с готовыми формулировками для формы, приказом и перечнем мер: `docs/legal/rkn-pack.md` (заполните поля в квадратных скобках).
- Уведомление об обработке персональных данных на pd.rkn.gov.ru до начала обработки (возможное исключение по ст. 22 уточнить у юриста, не полагаться на него).
- Данные хранятся в РФ (cloud.ru), это указывается в уведомлении.
- Политика (`docs/legal/privacy.md`): вписать оператора, реквизиты и контакт ответственного.
- Внутренние документы: приказ об ответственном, перечень мер защиты, порядок ответа на запросы субъектов.
- Уже есть в коде: согласие с отметкой даты при входе, хэш кода, удаление аккаунта, автоудаление неактивных аккаунтов через 24 месяца (`purgeInactive`), журналы nginx без IP.

## 3. Уход с GitHub

Целевая схема: Forgejo на ВМ в cloud.ru (`git.roadpdd.ru`) и отдельный runner.

1. Поставить Forgejo и runner, HTTPS через nginx, закрыть регистрацию, включить 2FA.
2. Перенести историю: `git clone --mirror`, затем `git push --mirror`. Issues и PR переносит встроенная миграция Forgejo (нужен токен GitHub).
3. CI: `.github/workflows/ci.yml` → `.forgejo/workflows/ci.yml`. `deploy-server.yml` выполняется на runner'е и копирует сборку на ту же ВМ без SSH; секрет `DEPLOY_KEY` не нужен.
4. Удалить `pages.yml`, обновить `AGENTS.md`, `README.md`, `docs/DEPLOY.md` (упоминания GitHub Actions и Secrets).
5. Настроить ежедневную копию Forgejo (репозитории и база) в объектное хранилище.
6. После проверки заархивировать репозиторий на GitHub и отозвать связанные токены и ключи.

Автоматизация PR в Claude Code сейчас работает через GitHub; после переезда её нужно перенастроить на новый хостинг.
