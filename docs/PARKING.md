# 06.4 — остановка, стоянка и аварийное обозначение

Реализация в `codex/06-04-parking`, от общей базы
`5cf9657dbc903cdb4b2f0fd096f6876d8c9f7513`. Других веток-зависимостей нет.
Общий реестр этапов обновляет финальный интегратор.

Проверки раздела 12 и пп. 7.1–7.2 используют локальные `pdd.json`,
`signs.json`, `markings.json`, `koap.json` (fetched 2026-10-20).
Тексты, URL источников, редакции и `legalCheck` разрешаются существующим
`lawRef` по дате ДТП; суммы штрафов в код не скопированы. В trace проверки
места записана выбранная норма с источником. Даты начала действия редакций
в корпусе по-прежнему требуют `TODO(legal-check)`.

## Причина и время

`analysis/stopping.ts` выделяет неподвижные интервалы по наблюдаемой
траектории. Пороги 0,1 м/с, 0,05 м смещения и 0,5 с наблюдения — параметры
распознавания модели, а не разрешённое время остановки по ПДД.

`Actor.stopContext.reason` задаётся по материалам: `passengers`, `cargo`,
`rest`, `other-voluntary`, `traffic`, `forced`. Для добровольной остановки
нужно также `intentional: true`. Нулевая скорость не устанавливает причину.
Остановка по сигналу/затору и вынужденная остановка не становятся стоянкой.

Длительность равна `durationBeforeStart + (frame - from) × DT`, в секундах.
Первое слагаемое учитывается только для интервала, начавшегося с первого
наблюдаемого кадра участника. Пустое значение означает неизвестную
предшествующую длительность, а не ноль. Для последующих интервалов начало
наблюдалось, поэтому предшествующая длительность равна нулю. Ровно 300 с —
остановка, более 300 с по иным добровольным причинам — стоянка. Для посадки/
высадки и груза превышение пяти минут само по себе не превращает остановку
в стоянку. При неизвестной длительности возможен только нижний предел;
если он уже превышает 300 с, стоянка установлена.

Контекст — установленные постоянные обстоятельства участника в данном
прогоне. Для нескольких остановок с разными причинами следует делать
отдельные реконструкции: временная шкала смены исходных фактов пока не
реализована. Не переносите добровольную причину на остановку после удара.

## Места и геометрия

Используются существующие `crosswalks`, `railwayCrossings`, трамвайные пути,
`sidewalks`, `routeStops`, разметка и геометрия дорог. Для остановки на самом
переезде сохраняется специальная проверка 06.1 / 12.10. Ей передаётся та же
классификация причины: одного старого `forcedStop: false` недостаточно.

`Scene.stopPlaces?: StopPlace[]` содержит только дополнительные измеренные
полигоны: локальный мост/тоннель/место под мостом, опасный поворот/перелом,
границу пересекаемой проезжей части, парковку/край тротуара/место инвалидов,
велополосу/дорожку/её пересечение, островок, сопряжение тротуара, обочину.
Обязательны `id`, `kind`, `boundary: Vec[]`, непустой `source`; допустимы
`roadId`, `signIds`. Контуры с нулевой площадью или самопересечением
отклоняются. Для разрешения по 6.4 и табличкам задайте ID знака в `signIds`.
`disabled-parking` или связанный 6.4 + 8.17 устанавливают назначение места.

Расстояния до перехода (5 м), остановочного места (15 м), переезда (50 м),
пересекаемой проезжей части/велопересечения (5 м) считаются от габарита,
включая груз. Для перехода учитывается курс стоящего ТС. У остановочного
места первична связанная 1.17.1/2; при её отсутствии — поперечный створ
указателя, без добавления поперечного расстояния до опоры знака. На самой
границе 5/15/50 м соответствующий запрет «ближе» отсутствует.

Автоматический внешний контур перекрёстка не подменяет край пересекаемой
проезжей части: без измерения возле него вывод неопределённый. Видимость
менее 100 м требует локального опасного поворота/перелома и нахождения на
проезжей части. Общий `road.features='bridge'` не запрещает остановку на
всей дороге.

Зазор 3 м можно задать обмером `clearanceMeters`; при его отсутствии
для параллельной постановки он рассчитывается до существующей сплошной
оси, линий 1.1/1.3/1.11 или противоположного края. Краевая 1.2 исключена.
Для сложных разделителей/непараллельной постановки нужен обмер. Допуск
направления для автоматического расчёта — параметр модели. РММ грузовика
задаётся отдельным `permissibleMaxMass`, не берётся из массы физической модели.

Один ряд/исключение двухколёсных, способ постановки, условия левой стороны,
обочина и край, долгий отдых вне населённого пункта, запреты тротуара и
помехи проверяются по геометрии и установленным фактам. Для фургона
регистрационный вид не предполагается легковым. Неизвестные разрешающие
условия дают «не определить»; отсутствие обочины или знака не выдумывается.

## Знаки и таблички

3.27–3.30 проверяются пространственно, даже если ТС уже находилось в зоне
при начале сцены. Учитывается сторона установки и пересечение габарита с
зоной вдоль оси дороги. Ближайший перекрёсток, конец населённого пункта,
3.31, длина зоны 8.2.1/2 и конечная 8.2.3 ограничивают зону. Выезд с
`role='adjacent'` её не прерывает. Установленное полевое/лесное/иное
второстепенное примыкание без соответствующих знаков задаётся на дороге
через `stopZoneJunction='nonterminating-minor'` и тоже не завершает зону. Измеренные `stopRule.fromS/toS` описывают
фасадные зоны 8.2.5/6. Для повторителя 8.2.4 без известного начала зоны
позади него вывод остаётся неопределённым. Утраченный перечень после
«Зона действия знаков может быть уменьшена» в корпусе не достраивается.

Дата/время — местные `env.accidentDate` плюс время прогона; часовой пояс
машины не используется. Проверки повторяются при границе минуты, смене
даты и переходе через 300 с. Нечётные/чётные числа и исключение 21:00–24:00
при одновременных противоположных 3.29/3.30 проверяются отдельно.

`Sign.stopRule` содержит `roadId`, `fromS/toS`, `weekdays` (пн=1…вс=7),
`hours: {from,to}` (HH:mm, конец не включительно), `scheduleDays`.
Для составных 8.5.5–7 вид дней (`working`, `nonworking`, `weekdays`) надо
подтвердить по установленной табличке: текст корпуса группирует эти номера.
Рабочие/нерабочие дни берутся из подтверждённого `env.dayStatus[YYYY-MM-DD]`;
переносы и праздники по памяти не создаются. UI позволяет задать статус
даты ДТП; следующие даты можно добавить в сцену.

Изображённая применимость 8.4 задаётся для каждого участника через
`stopContext.signApplicability: [{signId, applies}]`. Один глобальный флаг
на знаке не мог бы корректно описать разные ТС. При недостатке фактов
табличка остаётся неопределённой. 8.18 учитывает установленный знак
«Инвалид», 8.24 не создаёт запрета. Сохранены маршрутные/таксомоторные
исключения 3.27 только в соответствующих обозначенных местах. Для 3.28–30
отдельно нужны полный набор условий льготы инвалидов + опознавательный
знак, почтовая цветографика либо статус легкового такси + таксометр.

1.4 запрещает остановку, 1.10 — только стоянку. Привязка кузова к краевой
жёлтой линии использует рисовальный допуск 0,5 м, записанный в trace;
это не правовая дистанция. Старые ветки «4 с / 10 с неподвижности» удалены.
1.17.1/2 сохраняют назначение остановочных мест из 06.3.

## Дверь, водитель и предупреждение

`Actor.doorContext` хранит `opened`, `createsObstruction`, `operator`
(`driver`/`passenger`), необязательные `otherId`, `source`. Открытая дверь
без установленной помехи не доказывает 12.7. Отдельной геометрии двери нет,
помеха не называется доказанным контактом. `trace.contactProven=false`
здесь означает отсутствие установленного дверного контакта.

Для 12.8 используются `driverLeft`, `rollawaySecured`,
`unauthorizedUsePrevented`, `childUnder7Present`, `adultPresent`; ребёнок
младше 7 лет проверяется именно при установленной стоянке.
При вынужденной остановке отдельно проверяются 12.6, 7.1, 7.2.
Нулевая скорость не доказывает возможность отвода или бездействие.

`Actor.warningContext` содержит обстоятельства 7.1 (`accident`, `dazzled`,
`towedMechanical`, `childrenBoardingWithSign`, `otherDanger`),
`hazardAvailable`, `trianglePlaced`, `triangleDistance` или
`triangle: {x,y,source}`, `trianglePromptly`, `timelyWarningEnsured`,
`timelyVisibleToOthers`, `source`. Активный сигнал берётся из существующего
`vehicleSignalAt` с наблюдаемыми `waypointTimes`; при отсутствии команды
его состояние неизвестно, а не автоматически выключено. ДТП из timeline
также порождает обязанность. Ответ оценивается по наблюдаемому состоянию
к концу неподвижного интервала/наблюдения после контакта, без придуманного
срока в секундах.

Треугольник не отменяется неисправной/отсутствующей аварийной сигнализацией.
Измеряется минимум 15 м в населённом пункте, 30 м вне его; сам минимум не
доказывает своевременного предупреждения. «Незамедлительно» задаётся
установленным фактом, числового срока в норме нет. Неизвестная обязательность
предупреждения или неизвестное выполнение не дают административной части.

## Правовой слой и причинность

Части выбираются только в `analysis/legal.ts`, не в `rules.findings`.
В одном неподвижном интервале выбирается специальное основание вместо
набора общих частей: место инвалидов; тоннель/препятствие на проезжей части;
переход/тротуар; остановка маршрутных/такси; пути/второй ряд; запрет знаком
или разметкой; общее правило. Для пассажирской остановки исключена 12.19#3.1;
причина вынужденной остановки не создаёт добровольного парковочного состава.
Переезд обслуживается специальной 12.10 из 06.1. Предупреждение — 12.20
без выдуманного номера части. Учтён субъект КоАП существующего правового слоя.

Повышенные части 12.16/12.19 относятся только к Москве и Санкт-Петербургу;
Севастополь — обычная часть. Если город неизвестен, базовая часть и штраф
не предполагаются. 12.19#2 не требует этого регионального выбора.

Причинность парковочного нарушения всегда исследуется отдельно. Факт удара
не включает `causal`: trace сохраняет неопределённость механизма помехи/
закрытия обзора и отдельные технические оценки предотвращения другим
участником, если они рассчитаны. Контрфактического прогона без стоящего ТС
и натурной валидации нет. Двери, уход водителя, ребёнок и невыполнение 12.6
остаются с конкретным `TODO(legal-check)` по субъекту и составу; водительская
12.19 пассажиру автоматически не назначается.

## Совместимость и проверки

Все поля необязательны, `Scene.version=1` сохранён. `normalizeScene`
сохраняет новые известные значения, отбрасывает поддельные bool и
отрицательные/нечисловые длительности, оставляет измеренный ноль.
Старым сценам не дописываются причины/льготы и отрицательные факты.
После ДТП старые сцены могут получить `insufficient-data` по 7.1–7.2,
если сведений об аварийном обозначении нет. Это не установленное нарушение.

UI: свойства ТС → «Остановка, стоянка и аварийное обозначение»; свойства
знака → «Условия парковочного знака»; «Среда» → измеренные места.
Незавершённый полигон не попадает в сцену до сохранения источника/контура.
Четыре пары пресетов: 1.10, 4/5 м перед переходом, вынужденная остановка
14/15 м с сигнализацией, открывание двери с помехой/без неё.

`npm test`, `npm run build`. Независимые синтетические наблюдения в
`tests/stopping.test.ts` проверяют границы расстояний, времени, даты,
трёхзначные факты, части КоАП, сохранение данных и разделение причинности.
Это верификация реализации, не натурная валидация.
Дополнительная проверка реального UI: запустить `npm run dev`, затем
`node tools/check-parking-browser.cjs` с установленными Playwright/Chromium.
Путь к Playwright можно передать через `CRASHTEST_PLAYWRIGHT_MODULE`,
Chromium — `CRASHTEST_CHROMIUM_PATH`, URL Vite — `CRASHTEST_BROWSER_URL`.
Скрипт проверяет сохранение, пресеты, геометрию, знаки и ширину 390 px,
сохраняет снимки в `/tmp`.
