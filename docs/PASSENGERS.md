# Пассажиры и дети — 06.7

База реализации: `5cf9657dbc903cdb4b2f0fd096f6876d8c9f7513`,
`origin/codex/full-simulator-base-v1` (включает 06.3). Внешних веток-зависимостей нет.

## Исходные данные и миграция

Экспортируемые `Passenger` и `PassengerContext` определены в `src/passengers.ts`
и реэкспортируются из `src/scene.ts`. `Actor.passengers?: Passenger[]` — список
людей внутри конкретного ТС, а не самостоятельных движущихся участников.
`id` локален для ТС; предпочтительны условные идентификаторы без имён.
`age` — полные годы, `weightKg` — кг, `heightCm` — см. Место посадки:
`front`/`rear` для легкового, `cab`/`body` для грузового,
`motorcycle-rear`, `outside` (вне предусмотренных мест), `other`.

Поля пассажира: `beltUsed`, `helmetFastened`, `restraintUsed`, `restraintFits`
(соответствие росту и весу), `restraintInstalledCorrectly` (установка ДУУ и
размещение ребёнка по руководству). Отсутствующее логическое поле означает
неизвестное. Само по себе указание веса/роста не подтверждает пригодность ДУУ:
каталога сертифицированных кресел и их инструкций нет.

`Actor.passengerContext` содержит установленный по документам правовой класс
`vehicleClass: passenger-car | truck | other` (тип фургона не определяет класс),
оснащение `beltsProvided`, защиту водителя `driverBeltUsed` и
`driverHelmetFastened`, `passengerCapacity` (пассажирские места без водителя,
не число сидений из геометрии), `qualifyingLicenseYears` (стаж A/A1 для мотоцикла,
любой категории для мопеда, годы), `boardingWhileMoving`,
`doorsClosedWhileMoving`, `organizedChildren`.

Миграция добавочная, версия сцены остаётся 1. `normalizeScene` вызывает
`normalizePassengers`: старое отсутствие списка остаётся неизвестным,
`[]` означает явно заданное отсутствие пассажиров. Миграция не создаёт людей,
ремни или кресла. Некорректные значения удаляются без приведения строк к
boolean; дублирующиеся ID получают суффикс `-copy`. Возраст — целое 0–120;
рост/вес — положительные конечные числа; вместимость — целое >= 0.
У пешеходов и железнодорожных поездов пассажирские поля удаляются.

## Проверяемые требования

Тексты взяты из корпуса `src/data/pdd.json`: 2.1.2, 5.1, 22.1–22.9 и 24.8;
составы — из `src/data/koap.json`, 12.6 и части 12.23.

| Установленные условия | Проверка / предварительный состав |
| --- | --- |
| Ремни предусмотрены, водитель не пристёгнут | 2.1.2 / 12.6 |
| Мотоцикл: водитель/пассажир без застёгнутого мотошлема | 2.1.2, 5.1 / 12.6 |
| Мопед: водитель без застёгнутого мотошлема | 24.8 / 12.6 (для пассажира мопеда 12.6 автоматически не назначается) |
| Ребёнок младше 7, легковой или кабина грузового, ремни предусмотрены | Подходящее и правильно установленное ДУУ, одного ремня недостаточно / 12.23 ч. 3 |
| 7–11 включительно, заднее сиденье легкового или кабина грузового | Ремень либо подходящее и правильно установленное ДУУ / 12.23 ч. 3 |
| 7–11 включительно, переднее сиденье легкового | Только подходящее и правильно установленное ДУУ / 12.23 ч. 3 |
| От 12 лет, ТС с ремнями | Общий ремень / 12.6; возраст 12 не требует детского кресла |
| Заднее сиденье мотоцикла, младше 12 | Запрет 22.9 / 12.23 ч. 3 |
| Перевозка на мотоцикле/мопеде при установленном стаже права < 2 лет | 22.2(1) / 12.23 ч. 1 |
| Число пассажиров сверх установленной технической вместимости | 22.8 / 12.23 ч. 1 |
| Вне предусмотренных мест легкового/мотоцикла | 22.8 / 12.23 ч. 2; исключения для грузового не предполагаются |
| Заданная посадка/высадка в движении или незакрытые при движении двери | 22.7 / 12.23 ч. 1 |

Проверка правил находится в `src/analysis/passengers.ts`, отображение кодов
на статьи — в `src/analysis/legal.ts`. Неизвестные возраст, оснащение,
класс/место или требуемые обстоятельства дают «не определить» без состава.
Установленный провал одного обязательного условия достаточен для нарушения;
успех требует всех условий. При допустимой альтернативе ремень/ДУУ достаточно
подтвердить один вариант. Отсутствие ДУУ у 6-летнего с ремнём даёт только
детский состав, без дублирования того же факта как 12.6.

Правила перевозки, ремней и шлемов требуют наблюдаемого движения ТС
до первого столкновения. Факт `boardingWhileMoving` сам устанавливает движение
при посадке/высадке; время такого события отдельно не моделируется.
Отчёт не считает стоящее или отсутствующее в наблюдении ТС перевозящим людей
только по заполненному списку. Заключение о полной правомерности перевозки
по отсутствию нарушения не делается.

Источники через `lawRef` выбираются по `env.accidentDate`, санкции — по
`analysisDate ?? env.accidentDate`, как в общей модели. При отсутствии редакции
ПДД проверка остаётся неопределённой. Сохранены общие предупреждения корпуса
о неподтверждённых интервалах действия, а также общий механизм субъекта КоАП
(водитель младше 16 лет не получает административную квалификацию;
старое предположение совершеннолетия водителя при отсутствии возраста сохранено).

## Trace и контракт для 09

`passengerFacts(actor)` возвращает отдельную копию списка/контекста (или `null`
при отсутствии), единицы, `injuryModel: not-assessed` и
`protectionCoefficients: null`. Снимки находятся в
`Finding.trace.passengerFacts` и в
`report.technical.collisions[].trace.passengerFacts[]` с `actorId` ТС.
Препятствие не создаёт пассажирского снимка. Trace проверки содержит ID
пассажира, кадр наблюдаемого движения, исходный логический результат,
выбранные нормы с текстами/редакциями/URL и пределы метода.

Пассажиры не меняют массу ТС, траекторию, импульс или существующую оценку вреда.
Новые результаты травм по пассажирам не выдаются. Все пассажирские проверки
непричинные для столкновения; влияние защиты на травмы — отдельная задача 09.
Это не медицинский диагноз и не натурная валидация защиты.

## Ограничения и дальнейшая проверка

- Факты постоянны на весь прогон; нет временной шкалы посадки, пересадки,
  открывания дверей и смены защиты. Полноту списка устанавливает автор сцены.
- Детальная положительная проверка перевозки взрослых в кузове (22.1–22.5),
  категорий C/C1/D/D1, оборудования кузова, инструктажа, сопровождающих груз,

  Для кузова выводится необходимость отдельной проверки, включая отдельное установление
  запрета 22.2 на детей (возрастные определения вне 22.9 требуют legal-check). Общая вместимость не заменяет специальную проверку 22.3.
