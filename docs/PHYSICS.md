# Динамическое ядро 07.1 и динамический режим сцены 07.2

> Разделы 07.2 и далее (ветка `codex/parallel-physics`) добавлены поверх 07.1
> без замены ядра. Сводка по всей области — [handoff](handoffs/parallel-physics.md).

Дата редакции: 2026-10-22. Контракт `src/physics/index.ts`, схема параметров 1,
метод `four-wheel-dugoff-quasistatic-v1`. Это вычислительная верификация,
**не натурная валидация** автомобиля или ДТП.

07.1 предоставляет самостоятельное ядро с прямыми командами руления, тяги
и торможения. `simulate()` остаётся кинематическим. Переключатель
`env.physics`, редактор параметров/зон, регулятор маршрута и применение сил
к сценовому проигрывателю относятся к 07.2. Здесь они не подменены заглушкой.
Новые параметры влияют на общую массу и геометрию уже в кинематическом
расчёте, но не превращают его в динамический. Это указано в technical trace.

## Вызов и экспортируемые типы

```ts
import {
  syntheticVehicle, initialDynamicState, stepDynamics, dynamicSupport,
  parametersFromReference,
} from './physics';

// Только условный аналитический пример. Для реального ТС нужны свои источники.
const parameters = syntheticVehicle();
parameters.brakes.abs = 'ideal'; // явное допущение, не установленное оборудование
actor.dynamics = parameters;
const support = dynamicSupport(actor);
if (!support.supported) throw new Error(support.reason);
let state = initialDynamicState(actor);
const road = { mu: 0.8, source: {
  kind: 'synthetic' as const, description: 'Условная плоская поверхность',
} };
const result = stepDynamics(state, support.parameters,
  { steering: 0.02, drive: 0, brake: 0 }, road, { trace: true });
state = result.state; // прошло ровно 0.025 с

// Геометрия reference; оборудование задаётся отдельно, без скрытой шины/ABS.
const reference = parametersFromReference('commonroad-vehicle1', {
  tyres: parameters.tyres, brakes: parameters.brakes,
  drive: parameters.drive, loadTransfer: parameters.loadTransfer,
});
```

- `ParameterSource`: `kind=measured|reference|synthetic`, обязательное описание,
  необязательные URL, страница, дата получения. Метка measured принимается от
  автора исходных данных и сама по себе не удостоверяет измерение.
- `DynamicVehicleParameters`: `body` (масса, Iz, lf/lr, колеи, высота ЦМ,
  длина/ширина, смещение центра OBB), `tyres`, `brakes`, `drive`,
  `loadTransfer`; у каждой группы свой источник. База **вычисляется** как
  `lf+lr`, второго потенциально противоречащего поля нет.
- `DynamicState`: координаты **ЦМ**, курс, мировые vx/vy, yawRate,
  предыдущее инерциальное ускорение ax/ay в кузовных осях. Все поля сохранять
  для продолжения прогона; ax/ay — память переноса нагрузки.
- `DynamicControl`: угол передних колёс ±π/3 рад, drive ∈ [-1,1], brake ∈ [0,1].
  Одновременные тяга и тормоз не поддержаны и отклоняются. Положительный drive
  тянет вперёд; отрицательный тормозит поступательное движение и затем даёт реверс.
- `DynamicRoad`: mu ≥ 0 и источник. Уклоны/зоны сюда ещё не интегрированы.
- `evaluateForces`: четыре `WheelForce`, сумма сил/момента, флаг потери контакта;
  не зависит от маршрута. `dugoffTyre` и `lockedTyre` доступны для проверки отдельно.
- `stepDynamics`: новый state и необязательный `DynamicStepTrace`; не меняет входы.
  В trace есть исходные параметры/источники, единицы, формулы, начальное состояние,
  команды и по каждому подшагу силы, нагрузки, slip, энергия и масштаб импульса.
  Это отдельный технический контракт без правил/правовой оценки.
- `dynamicSupport` возвращает discriminated union с причиной неподдержки;
  `initialDynamicState` отклоняет неподдержанный actor. `actor.speed` переводится
  из км/ч в м/с ровно при инициализации, знак заднего хода сохраняется.

## Оси и механика

Как в `geom.ts`: x кузова вперёд, y вправо, yaw и руление положительны
по часовой стрелке на экране. Колёса FL/FR имеют x=lf, RL/RR x=-lr;
левые y=-track/2, правые y=+track/2. Передние колёса имеют общий угол,
геометрия Аккермана и самоустанавливающий момент шины не моделируются.

```text
Vcontact_body = (u-r*y, v+r*x)
Vwheel = rotation(-delta) * Vcontact_body
Fbody = rotation(delta) * Fwheel
Mz = sum(x*Fy_body - y*Fx_body)
m*dVworld/dt = rotation(heading)*sum(Fbody)
Iz*dr/dt = Mz
```

Использование мировых скоростей сохраняет импульс при свободном вращении
кузова. Эквивалентная кузовная запись: du/dt=r*v+Fx/m,
dv/dt=-r*u+Fy/m. Все силы — N, моменты — N·m, масса — kg,
Iz — kg·m², расстояния — m, время — s, углы — rad.

Перенос нагрузки на плоской дороге, g=9.81 m/s²:

```text
L = lf+lr
Fzf = m*(g*lr-ax*h)/L; Fzr = mg-Fzf
dFzf = m*ay*h*frontRollFraction/trackFront
dFzr = m*ay*h*(1-frontRollFraction)/trackRear
Fz_FL = Fzf/2+dFzf; Fz_FR = Fzf/2-dFzf
Fz_RL = Fzr/2+dFzr; Fz_RR = Fzr/2-dFzr
```

Доля переднего момента крена — **явная редукция подвески**, не измеренный
универсальный коэффициент. Используется ускорение предыдущего подшага.
Нагрузки неотрицательны; при ограничении сумма остаётся mg, а `wheelLift=true`
предупреждает, что дальнейшее пространственное движение не моделируется.

## Dugoff, сцепление и квазистатические исполнительные механизмы

Конвенция шины: V=|Vx|, d=sign(Vx), κ=(d·Rω−V)/V > -1,
tanα=Vy/V. Для движения назад меняется знак продольной силы d,
поперечная сила всегда против бокового скольжения. При малых V в tanα
используется max(V, 0.1 m/s); это численная регуляризация.

```text
qx = Cx*κ/(1+κ)
qy = -Ca*tanα/(1+κ)
z = hypot(qx/(muX*Fz), qy/(muY*Fz))
lambda = 1/(2*z)
f(lambda) = 1, если lambda>=1; lambda*(2-lambda) иначе
Fx = d*qx*f; Fy = qy*f
muX = mu*frictionScaleX; muY = mu*frictionScaleY
```

Это нелинейная brush-функция. Например, при qy=-4000 N и μFz=4000 N
получаем λ=0.5, f=0.75, Fy=-3000 N, а не обрезку до -4000 N.
Анизотропный эллипс — явно введённое расширение изотропного Dugoff:
`(Fx/(muX*Fz))²+(Fy/(muY*Fz))² ≤ 1`. При μ=0 или Fz=0 сила нулевая.
У чисто продольного Dugoff в нелинейной ветви `|F|=A-A²/(4|q|)`, A=muX·Fz.
Отсюда `|q|=A²/(4(A-|F|))`; линейная ветвь q=F при |F|≤A/2.

Ядро не интегрирует ω и не приписывает автомобилю неизвестную инерцию колеса.
Оно преобразует квазистатическую команду продольной силы в κ через этот
обратный чисто продольный закон: `κ=q/(Cx−q)`. Затем **обе** силы вычисляются
полным combined-slip Dugoff; на повороте продольная команда может не выполниться.
Для тяги q ограничено 0.999·Cx (область положительного κ). Ограничение
силы 0.999·A — численное приближение асимптоты, не эмпирический максимум шины.
Реальных переходных процессов двигателя, трансмиссии и колеса нет.

Тормозная команда делится по `frontFraction` и поровну между колёсами оси;
тяга — на переднюю, заднюю либо все четыре шины. При `abs=ideal` запрос
ограничивается 0.999·A. Это идеальный ограничитель силы: у принятого
постоянного μ Dugoff нет конечного пика slip, поэтому заявлять настоящий
алгоритм ABS или измеренную целевую пробуксовку нельзя. `unknown` допускает
движение без тормоза, но команда brake>0 вызывает ошибку.

При `abs=disabled` и запросе тормозной силы ≥A колесо считается блокированным.
Тогда применяется **отдельная** максимальная диссипация Кулона по эллипсу:

```text
D = hypot(muX*Vx, muY*Vy)
Fx = -Fz*muX²*Vx/D; Fy = -Fz*muY²*Vy/D
```

При D=0 силы нулевые. Эта ветвь не называется конечным slip Dugoff.
Граница переключения не моделирует время блокировки/разблокировки колеса.
Диссипация шины проверяется по относительной скорости контакта:
`Fx*(-d*κ*V)+Fy*Vy ≤ 0`. Тяга может добавлять энергию кузову; это работа
привода, не отрицательная диссипация шины.

## Интегратор, покой и проверки

Внутри DT=25 ms — пять фиксированных подшагов по 5 ms. Для проверки
сходимости разрешён фиксированный делитель кадра от 0.1 до 5 ms
(проверен также 2.5 ms). Адаптивного шага, случайности и проекции на путь нет.
Импульсное обновление скорости использует силы в начале подшага;
координаты/курс — трапециевидное среднее скоростей. Порядок по силам первый.

Для пассивной суммарной силы P=Fworld·Vworld+Mz·r<0:
`Q=|Fworld|²/m+Mz²/Iz`, `scale=min(1,-P/(dt*Q))`.
Все силы и моменты импульса умножаются на один scale. Тогда
`ΔE=dt*scale*P+dt²*scale²*Q/2≤0`. Это численная защита от смены знака
при остановке/малой скорости, а не дополнительное сцепление.
В trace силы даны **до** этой коррекции и рядом указан `impulseScale`;
применённая средняя сила = force·impulseScale. После пассивного затухания
остатки скорости и yawRate <1e-10 обнуляются. Свободное движение без сил
это обнуление не затрагивает. Покой не создаёт самопроизвольный реверс.
Если движение полностью прекратилось внутри подшага, координаты/курс
интегрируются только до момента остановки (`motionSeconds=dt*scale`),
затем сохраняются. Это отдельно проверено при скорости от 0.001 m/s:
использование всего dt завышало бы малый остановочный путь.

`tests/physics.test.ts` проверяет независимо от регулятора маршрута:

## Каталог, лицензия и неподдержанные случаи

В `VEHICLE_REFERENCES` три **reference chassis**: Ford Escort, BMW 320i,
VW Vanagon. Значения из закреплённых YAML CommonRoad сопоставлены с
округлёнными таблицами 4 и 6 PDF. Это не каталог измеренных характеристик
всех легковых автомобилей/фургонов. Базу, массу и геометрию не переносим
на автобусы/поезда. Оборудование, тормозные силы, ABS, шины и распределение
крена для каждого применения должны быть заданы отдельно с источниками.
`syntheticVehicle()` — только условная проверочная машина.

Производные данные CommonRoad: Copyright 2020 Technical University of Munich,
Professorship of Cyber-Physical Systems. Полная BSD-3-Clause сохранена в
`public/licenses/CommonRoad-BSD-3-Clause.txt` и попадает в `dist/licenses/`.
Чужой код не копировался. URL, SHA-256 и даты получения —
[physics-07-01-sources.json](research/physics-07-01-sources.json).
PDF/иллюстрации Brandt не распространяются.

`Actor.dynamics` необязателен; версия старых сцен остаётся 1. Отсутствие поля
не создаёт параметры. Неверные значения/источники отклоняются при нормализации.
`actorSpec` и `dimsOf` используют body.mass/length/width; те же значения
попадают в существующий импульс столкновения и technical.
`bodyCenterOffset` явно отделяет центр OBB от ЦМ. У reference это условный
ноль с источником synthetic: положение геометрического центра не измерено.
Высота кузова остаётся прежним классовым значением `VEHICLES`, не измерением
прототипа; она не участвует в плоской динамике.

Динамика допускает явно описанные четырёхколёсные car/suv/van/truck/bus/
trolleybus. Для остальных нет автоматического аналога; двухколёсные,
пешеходы, гужевые, рельсовые, сочленённые и многоосные ТС этим ядром
не описываются. Наличие в `vehicleTypes` автобусного типа не подтверждает
применимость конкретному автобусу: это ответственность автора набора.
Груз с ненулевой отдельно заданной массой отклоняется: без нового согласованного
набора mass/Iz/CG нельзя менять только массу. Нельзя обходить это ограничение,
объявляя массу пустой машины массой загруженной. Свесы без дополнительной массы
сохраняют прежний геометрический контракт.

## 07.2: динамический режим сцены (`env.physics`)

`Env.physics?: 'kinematic' | 'dynamic'`. Отсутствие поля — прежний
кинематический («упрощённый») симулятор без изменений; `Timeline.physics.mode`
и метки методов это фиксируют. `simulate(scene, options?)` в режиме `dynamic`:

- маршрут (`Actor.path`) — **намерение**. Регулятор выдаёт руль/тягу/тормоз,
  координаты считает интегратор сил (подшаг ≤5 мс внутри 25 мс). Притягивания
  кузова к линии нет: при насыщении шин ТС уходит со следа (тест: дуга R=40 м,
  μ=0,4 — отклонение <1 м при 0,8·√(μgR) и >3 м при 1,2·√(μgR));
- руление: pure pursuit (Coulter 1992, §2; задняя ось; реверс с обратным знаком
  кривизны) или Stanley (Hoffmann, Tomlin, Montemerlo, Thrun, ACC 2007,
  doi:10.1109/ACC.2007.4282788; только движение вперёд, реверс — pure pursuit);
- профиль скорости: плановая скорость повторяет логику узлов прежнего
  симулятора (огибающая √(V²+2b·Δs)), P-контур 1,5 1/с и закон остановки
  a=v²/(2·остаток). Настройки регулятора — численные (`CONTROLLER_TUNING_SOURCE`,
  kind=synthetic), переопределяются в `extensions.physics.vehicles[id].controller`;
- тормозной привод: чистая задержка t2 и линейное нарастание t3 от начала
  приложения (`BrakeActuator`). Без t2/t3 — явно идеальный привод
  (assumption в Timeline). Реакция t1 — только на явно заданный момент
  опасности `hazard.at` (сам момент не выводится регулятором);
- остановка в точке маршрута фиксируется только в покое у точки или за ней
  (`waypointTimes` — фактическое время), реверс — после покоя;
- поддерживаются только четырёхколёсные ТС с явными параметрами и ABS ≠ unknown.
  Иначе `PhysicsUnsupportedError` со списком участников (без перехода на
  кинематику). Пешеходы, трамваи/поезда, двухколёсные/СИМ сохраняют собственные
  кинематические модели с меткой метода; гужевая повозка — unsupported.

Проверка тормозного пути по сценовому прогону (1 мс): v(t1+t2+0,5t3)+v²/(2j)
в пределах 1 %, точная форма для линейного нарастания `… − j·t3²/24` — 0,1 %.

### Измеренные зоны и уклон

`PhysicsZone` (`extensions.physics.zones`): замкнутый контур (граница входит в
зону), μ, направление зоны, продольный/поперечный уклон (безразмерные; продольный
положителен на подъём вдоль направления, поперечный — подъём вправо от него),
неровность (профиль/IRI), приоритет, источник. Разрешение **по полям**: для μ и
для уклона отдельно побеждает зона с наибольшим приоритетом; равный приоритет с
разными значениями — ошибка, не «первое совпадение». μ берётся в точке контакта
каждого колеса (split-μ), уклон — в ЦМ. Вне зон: μ покрытия сцены (классовое
значение, kind=synthetic), уклон неизвестен → горизонтальная плоскость с
явным допущением. Неровность сохраняется в trace; влияние на силы не рассчитано
(TODO(source-check): модель передачи), множитель μ не подставляется.

Уклон в ядре: `G=-m·g·∇z/√(1+|∇z|²)`, нормальная сумма `W=m·g/√(1+|∇z|²)`,
продольный перенос `Fzf=(W·lr−m·ax·h)/L`, где ax/ay — удельная сила шин.
Координаты сцены трактуются как развёртка поверхности (ошибка проекции на
горизонтальную плоскость 1−cosθ, 0,5 % при 10 %). В покое на уклоне —
статическое удержание по агрегированному эллипсу (статический μ = заданному μ,
допущение). Проверки: свободный скат g·sinθ, блокированное торможение под уклон
v²/(2g(μcosθ−sinθ)) в пределах 1 %, удержание/срыв, граница μ с переходом колёс
по одному и переносом нагрузки (независимый кусочный расчёт, 1 %).

Сопротивление качению (`rollingResistance`) и блокировка отдельных колёс
(`DynamicControl.wheelLock`) — необязательные явные поля; без них прежние
результаты 07.1 побитово совпадают.

`Track.dynamics` содержит по кадрам скорости, руль/тягу/тормоз, μ/зону/признаки
известности и по колёсам нагрузку, силы, использование эллипса и режим — для
визуализации (UI сам не пересчитывает физику).
