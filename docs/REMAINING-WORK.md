Названия сверены с официальными страницами 21 октября 2026 года.
Распределение задач — моя практическая рекомендация, не гарантия качества
и не независимый сравнительный тест моделей.

- GPT-6.1 Sol в Codex, reasoning high: основной разработчик и интегратор.
- Claude Sonnet 5.5 в Claude Code: формы, редактор, документы и мобильный UX.
- Claude Opus 5.5: сложная физика, оптимизация и разбор взаимосвязанных условий.
- GPT-6 Astra, reasoning high: исследование источников и независимая проверка

Sol доступен в Work/Codex, а не в обычном окне ChatGPT; доступ зависит
от плана и настроек. Для выполнения промптов агенту нужен доступ к репозиторию,
терминалу и тестам. Если нужна одна модель на всю работу, мой выбор —
GPT-6.1 Sol high в Codex; критические формулы проверять вторым агентом.

## Общие правила выполнения — обязательны для каждого промпта

1. Работать в существующей codex/04-full-simulator. Не пересоздавать её от 03,
   не повторять слияние 02: оно уже выполнено коммитом 6747819. Не менять main,
   не делать rebase, reset чужой работы или force-push. Сначала проверить
   git status/git log; незавершённые изменения сохранить и разобраться
   в их принадлежности. Обновлять чистую рабочую копию без переписывания истории.
2. Прочитать AGENTS.md и docs/codex/README.md, если они появились, затем
   docs/FULL-SIMULATOR.md, docs/FULL-SIMULATOR-REQUEST.md и профильные документы.
   Отсутствие первых двух файлов уже зафиксировано; не придумывать им замену.
3. Выполнить только выбранное задание после его зависимостей. Для крупных
   заданий 13, 16 и 18 сначала выделить проверяемые подэтапы и фиксировать
   каждый отдельным коммитом в рамках исходного номера этапа. Сохранить
   совместимость сцен, даты редакций норм, разделение technical/rules/legal
   и trace с исходными данными, формулами, допущениями и пределами метода.
4. Не подставлять неизвестные факты значением false. Не придумывать источники,
   лицензии, эмпирические коэффициенты, штрафы или вероятности. Неизвестное —
   явная неопределённость. При внешнем препятствии поставить конкретный
   TODO(legal-check)/TODO(source-check), описать частичную готовность и сделать
   остальную часть задания. Не выдавать синтетический тест за натурную валидацию.
5. Добавить содержательные проверки, включая независимые наблюдаемые треки
   для ПДД и аналитические/опубликованные примеры для физики. Изменения UI
   проверить в Chromium. Сохранять рабочими существующие пресеты.
6. Перед фиксацией npm test и npm run build должны пройти. Красные проверки
   не объявлять выполненным этапом. Обновить FULL-SIMULATOR.md и ограничения
   README, перечислить новые TODO. Отдельный коммит с префиксом исходного
   «Этап NN: …», затем git push -u origin codex/04-full-simulator.
7. В ответе дать SHA, результаты проверок, реализованные пункты, ограничения
   и незакрытые источники. Не начинать следующее задание в том же запуске.
   Не публиковать npm-пакеты, не сливать main и не развёртывать сервисы.
8. В финале всей обязательной работы составить полный/частичный статус
   требований и реестр TODO(legal-check)/TODO(source-check), подтверждённый
   поиском по репозиторию; обновить README с фактическими ограничениями.

Все промпты ниже ссылаются на эти правила, чтобы их можно было копировать
по одному в новый запуск агента с открытым репозиторием.
