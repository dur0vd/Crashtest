# Раздел 19 и публичный порт правил

Вход `src/rules/port.ts`: `createRulesPort(): RulesPort`, контракт версии 1.
`describe(project)` выдаёт RFC6901-пути, включая экранирование ID. `evaluate`
принимает наблюдаемый `Timeline` с базовым шагом 25 мс; другой шаг или неполный
трек возвращает `insufficient-data`, а не фиктивный отчёт. DOM не используется.

Новые факты: `extensions.rules.lighting`: `timeOfDay: day|twilight|night`,
`insufficientVisibility: boolean`, `source`, `actors: { [actorId]: {...} }`.
Набор полей приборов и условий доступен в `describe`. Отсутствие/null —
неизвестность, строка `"false"` не является boolean. Факты постоянны за явно
заявленный период наблюдения; динамической оптики и вычисления освещённости нет.
Сумерки сами по себе не устанавливают достаточность/недостаточность видимости.
Применимость 19.1 учитывает отдельно буксировку: её состояние задаётся имеющимся
`Actor.warningContext.towedMechanical`; неизвестность не равна отсутствию.

Проверяются 19.1–19.7, 19.10–19.11 и движущийся участник по 7.1.
19.8/19.9 отменены; не создаются действующие обязанности из их номеров.
Порог встречного разъезда 150 м относится к переключению дальнего света.
Факт ослепления берётся только из `warningContext.dazzled`; риск ослепления
других — отдельное установленное наблюдение, а не следствие одного расстояния.
Снижение скорости/остановка/полоса после ослепления проверяются по наблюдениям.
Активность аварийной сигнализации берётся только из `vehicleSignalAt` с
фактическими `waypointTimes` и командами `Waypoint.signal`. Проверка неподвижных
участников остаётся в существующем `analysis/stopping.ts`.

Нарушения света не получают причинную связь из контакта. Правовой этап выбирает
12.20 для соответствующего субъекта, 12.29 для немеханических участников с
учётом возраста; соблюдение и неизвестность не создают состав. На первом
подэтапе ограничения квалификации СИМ из базы сохраняются для отдельной сверки.
