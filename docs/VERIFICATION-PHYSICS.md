# Верификация физики и численных методов (параллельный чат 1)

Верификация — проверка, что код считает заявленное: каждая строка сравнивает
реализацию с независимым аналитическим результатом, ручным расчётом или
опубликованным значением. Таблица генерируется тестом
`tests/verification/physics-verification.test.ts`:

```sh
PHYSICS_VERIFICATION_OUT=<файл таблицы> npx vitest run tests/verification
```

Полные наборы проверок — в `tests/physics*.test.ts`, `tests/expert-*.test.ts`,
`tests/reconstruction.test.ts`, `tests/video-math.test.ts`, `tests/physics-port.test.ts`.

## Валидация (согласие с реальностью)

**Не выполнена.** Открытые натурные данные с лицензией, допускающей
распространение (краш-тесты NHTSA, испытания торможения, наезды на манекены),
в репозиторий не включены и не загружались. Строки «опубликованное значение»
выше (Augenstein 2003, Tefft 2011, Becker 2015) проверяют только воспроизведение
опубликованной параметризации/вывода, а не точность модели для конкретного ДТП.
Параметры CommonRoad — reference-шасси, не измерения конкретного ТС. Регулятор —
численная настройка, не модель водителя. Подготовка валидационного набора с
лицензиями и допусками — этап 17 (интегратор).
