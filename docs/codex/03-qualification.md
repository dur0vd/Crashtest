# 03. Слой квалификации: техническое отдельно от правового

## Промпт

```
Прочитай AGENTS.md. Сейчас src/analysis.ts (~1500 строк) смешивает в одном проходе расчёты, поиск нарушений
и юридическую квалификацию. Для экспертного применения их надо разделить.

Сделай рефакторинг без изменения результатов существующих тестов (кроме исправленных в задаче 01):
1. src/analysis/technical.ts — только технические факты: события (пересечение стоп-линии, сигнал светофора
   в момент, положение на полосе, скорость в точке), столкновения, момент возникновения опасности,
   остановочный путь, техническая возможность, расчётные диапазоны. Никаких ссылок на КоАП/УК.
2. src/analysis/traffic-rules.ts — сопоставление фактов с требованиями ПДД: «требование п. X», «выполнено /
   не выполнено / не определить», причинная связь (техническая: устранение нарушения предотвращало ДТП?).
3. src/analysis/legal.ts — ориентировочная квалификация: состав КоАП/УК, субъект (motorized,
   licenseRequired, возраст пешехода — дети до 16 лет не субъекты КоАП), поглощение составов
   (см. задачу 01), отягчающие, санкция в редакции на дату.
4. Тип Report получает три раздела: technical, rules, legal. UI показывает их отдельными блоками с
   заголовками «Технические выводы», «Соответствие ПДД», «Ориентировочная правовая оценка (решение
   принимает суд/орган)».
5. Каждый вывод хранит trace: какие входные данные и промежуточные значения к нему привели
   (например, { v0: 13.9, t1: 1.0, t2: 0.2, j: 6.8, S: 30.7, available: 40.6 }). Это основа будущего отчёта.
6. Статусы вместо «guilty/clean»: «нарушение в причинной связи», «нарушение без причинной связи»,
   «нарушений не выявлено», «недостаточно данных». Слово «виновен» из интерфейса убрать.

Проверка: все существующие тесты проходят (обнови ожидания только там, где меняется формат, а не суть);
npm run build.
```
