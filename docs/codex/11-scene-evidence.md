# 11. Ввод данных с места ДТП

## Промпт

```
Прочитай AGENTS.md. Для реконструкции нужно не рисовать «как было», а вводить зафиксированные следы и
измерения и уже по ним восстанавливать движение. Добавь в Crashtest слой «Вещественная обстановка».

1. Объекты в src/scene.ts (новая коллекция evidence) и инструменты в src/editor.ts:
   - следы торможения/юза/бокового скольжения (ломаная, длина, ширина, от какого колеса, прерывистость ABS);
   - осыпь стекла и пластика (область), следы жидкостей, задиры на покрытии;
   - место столкновения (точка/область, кем установлено, степень уверенности);
   - конечные положения ТС и тела пешехода (положение, курс);
   - повреждения ТС: зона, глубина деформации C1…C6 по высоте/ширине (для CRASH3 в задаче 08);
   - знаки, разметка, светофорный цикл — как зафиксированы (с источником: схема, фото, данные ЦОДД).
   У каждого объекта: источник (схема ДТП, протокол осмотра, фото №, измерение рулеткой/дальномером),
   погрешность измерения, комментарий.
2. Привязка: система координат от двух неподвижных ориентиров (угол дома, опора освещения) как на
   схеме ДТП; ввод размеров «от ориентира А по оси X — 12,4 м».
3. Подложка: загрузка фото схемы/ортофото/спутникового снимка, масштабирование по двум точкам с известным
   расстоянием, прозрачность. Импорт геометрии дорог из OpenStreetMap (по координатам) — опционально,
   с атрибуцией OSM.
4. Фото с места: прикрепление к объектам, хранение оригинала с EXIF и хэшем (подготовка к задаче 15).
5. Валидация ввода: противоречия (след длиннее, чем позволяет скорость; конечное положение за
   препятствием) — предупреждения.
6. Экспорт масштабной схемы ДТП в PDF/SVG в виде, близком к принятому оформлению схемы места ДТП
   (условные обозначения, масштаб, ориентиры, подписи понятых/участников как пустые поля).

Проверка: npm test, npm run build; сцены без evidence открываются как раньше.
```
