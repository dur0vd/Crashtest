# 14. Отчёт в структуре заключения эксперта/специалиста

Ветка: `codex/14-expert-report` ← от `codex/03-qualification`

## Промпт

```
Работай в отдельной ветке codex/14-expert-report. Создай её от codex/03-qualification (если в origin её нет — остановись и сообщи, что сначала нужна та задача).
Не коммить в main и в чужие ветки. В конце: npm test и npm run build зелёные, коммит, git push -u origin codex/14-expert-report.

Прочитай AGENTS.md. Нужен экспорт результатов Crashtest в документ, который эксперт или специалист может
положить в основу своего заключения, а аварийный комиссар — приложить к материалам. Используй разделы
отчёта technical / rules / legal и trace из задачи 03.

1. Генерация PDF в браузере (pdf-lib или аналог, шрифт с кириллицей встроить) и DOCX (для правки).
2. Структура (ориентир — требования к содержанию заключения в ст. 25 ФЗ «О государственной судебно-
   экспертной деятельности в РФ» и ст. 204 УПК РФ; TODO(legal-check) сверить перечень):
   - вводная часть: кто, когда, по чьему запросу, поставленные вопросы (поле ввода вопросов
     «Какова скорость…», «Имел ли водитель техническую возможность…»);
   - исходные данные: перечень материалов (схема, протокол осмотра, видео, фото) с хэшами;
     принятые исходные данные с источниками и погрешностями;
   - исследование: методы, формулы с подстановкой чисел, промежуточные результаты, графики, схемы на
     ключевые моменты, результаты Монте-Карло и чувствительности;
   - выводы: ответы на каждый вопрос, категоричные или вероятностные — в зависимости от разброса;
   - отдельный раздел «Соответствие действий участников ПДД (с технической точки зрения)»;
   - правовая оценка — только в режиме «аварийный комиссар / учебный», в экспертном режиме по умолчанию
     выключена (эксперт не решает правовые вопросы);
   - приложения: параметры, версия программы, хэш сцены, журнал изменений (задача 15).
3. Шаблоны отчёта: «Справка аварийного комиссара», «Расчёт для специалиста», «Учебный разбор».
4. Тексты выводов — шаблонные, без оценочных формулировок («виновен»); проверка: в отчёте нет слова
   «виновен» и нет вывода без ссылки на расчёт.
5. Тест: снимок (snapshot) текстовой части отчёта для 3 пресетов; PDF открывается и содержит хэш сцены.

Проверка: npm test, npm run build.
```
