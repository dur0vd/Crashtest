# 20. Объединение всех веток

Ветка: `codex/integration` ← от `main` + влить все `codex/01…19`

## Промпт

```
Работай в ветке codex/integration. Создай её от актуального main.
Не коммить в main напрямую. В конце: git push -u origin codex/integration.

Прочитай AGENTS.md и docs/codex/README.md. Все задачи 01–19 выполнены, каждая в своей ветке codex/NN-…
Объедини их в codex/integration.

1. git fetch origin. Проверь, что все 19 веток есть в origin; если какой-то нет — перечисли отсутствующие
   и остановись.
2. Вливай строго по порядку номеров: codex/01-fix-known-bugs, codex/02-law-versions, … codex/19-training-mode
   (git merge --no-ff, без rebase и без squash — история веток сохраняется). Ветки, уже вошедшие в
   другие, вольются без изменений — это нормально.
3. После каждого merge: npm ci (если менялся package-lock.json), npm test, npm run build. Если сломалось —
   исправь в отдельном коммите «Интеграция: …» сразу после этого merge, не откладывай.
4. Конфликты: сохраняй поведение обеих сторон. Особое внимание — src/scene.ts (миграции формата сцены
   должны выстроиться в одну цепочку версий), src/law.ts и src/data/*.json (не терять редакции норм),
   src/analysis/* и src/ui.ts. Если конфликт меняет смысл правовой нормы или физической формулы и
   выбрать нельзя — оставь обе версии под флагом, добавь TODO(merge-check) и опиши в итоговом сообщении.
5. Финальная проверка: npm test, npm run build, npm run validation-report (из задачи 17), все пресеты
   открываются и считаются в обоих режимах физики; старые сохранённые сцены (из main до интеграции)
   открываются.
6. Обнови README.md: что умеет программа теперь, раздел «Ограничения», ссылки на docs/VALIDATION.md,
   docs/PRIVACY.md, docs/LEGAL.md.
7. Итог: список влитых веток, список коммитов «Интеграция: …», все TODO(legal-check) и TODO(merge-check),
   оставшиеся в коде (grep), — их должен проверить человек перед слиянием в main.
```
