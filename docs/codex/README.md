# Промпты для Codex: от учебного симулятора к инструменту реконструкции ДТП

Каждый файл в этой папке — одна задача размером с один PR. Скопируйте текст из блока «Промпт»
в Codex целиком: промпт самодостаточный, общие правила проекта Codex прочитает в `AGENTS.md` в корне.

Выполнять по порядку: следующие этапы опираются на предыдущие. Внутри этапа задачи с пометкой
«параллельно» можно запускать одновременно.

## Что значит «можно использовать у аварийного комиссара и в суде»

Программа сама по себе не доказательство. В суде доказательство — заключение эксперта
(ст. 204 УПК РФ, ст. 26.4 КоАП РФ, ст. 86 ГПК РФ) или специалиста, а программа — его инструмент.
Поэтому требования к ней такие:

1. **Обоснованность** — каждая формула и каждый параметр имеют источник (методика, ГОСТ, научная работа).
2. **Проверяемость** — любой расчёт можно пересчитать вручную по отчёту: исходные данные, формулы, промежуточные значения.
3. **Воспроизводимость** — та же сцена на той же версии даёт тот же результат; версия движка и хэш входных данных есть в отчёте.
4. **Неопределённость** — результат дан диапазоном (скорость 52–61 км/ч), а не одним числом, с анализом чувствительности.
5. **Валидация** — опубликованный отчёт о сравнении с краш-тестами и аналитическими решениями.
6. **Разделение ролей** — технические выводы отдельно от правовой оценки; вину устанавливает суд.
7. **Нормы на дату ДТП** — ПДД, КоАП и УК в редакции, действовавшей в день происшествия.

Каждая задача делается в **своей ветке** `codex/NN-…`. В main ничего не коммитится, пока не готово всё:
в конце задача 20 сливает все ветки в `codex/integration`, а её уже вливают в main одним PR.

## Как давать задачу Codex

- Один промпт — одна задача. Не склеивайте этапы: большие PR хуже проверяются.
- После каждой задачи читайте diff глазами, особенно `law.ts` и `src/data/*.json`: правовые данные должен
  проверить человек.
- Если Codex оставил `TODO(legal-check)`, закройте его сами или отдельной задачей.
