# Редакции норм на дату ДТП

`env.accidentDate` — локальные дата и время места ДТП (`YYYY-MM-DDTHH:mm`).
Новые и старые сцены без этого поля получают текущие дату и время.
`lawRef(id, scene.env.accidentDate)` выбирает **единственную** редакцию с интервалом
`[validFrom, validTo)`. Дата ДТП берётся как календарная дата места происшествия,
без пересчёта через UTC. Неизвестная дата, пробел или пересечение интервалов
не разрешают использовать текущую редакцию: текст и санкция отсутствуют,
в отчёт попадает `TODO(legal-check)`.

Каждый пункт ПДД, знак, разметка и часть КоАП/УК содержит `revisions`:

```ts
{
  validFrom: string; // YYYY-MM-DD, включительно
  validTo?: string;  // YYYY-MM-DD, исключительно
  text: string;
  sanction?: string; // дословно из текста этой части
  source: { url: string; docTitle: string; revisionDate: string };
  effectiveSource?: string; // источник проверки вступления в силу
  legalCheck?: string;
}
```

Верхнее поле `text` в JSON — совместимый со справочником снимок последней
загруженной редакции, который сборщик получает из `revisions`. Разбор его
не использует как запасной текст. `LAW` содержит метаданные и историю;
его санкция для сегодняшней даты и санкция `lawRef` получаются из корпуса,
а не из вручную сокращённых сумм. `sanctionOf` извлекает абзац «влечет…» /
«наказывается…», исключая строку об отменённых соседних частях.

Ссылки из `restrictions.ts` проходят через общий сборщик отчёта в `analysis.ts`:
все `findings.refs`, `verdicts.legal.refs` и `duties.refs` разрешаются с датой
сцены. В сериализуемом `Report` сохраняются `accidentDate`, `laws` (текст,
санкция, выбранная редакция, источник, предупреждение) и `legalWarnings`.
Их должен использовать будущий PDF. В UI источник и дата редакции видны
рядом с нормой; справочник отдельно показывает последнюю загруженную редакцию.

## Ручное обновление (без сети в CI)

```sh
python3 -m pip install beautifulsoup4 lxml
python3 tools/fetch-law.py /tmp/crashtest-law
python3 tools/build-law.py /tmp/crashtest-law
python3 tools/test-law-tools.py
npm test
npm run build
```

Для нового обновления текущего корпуса используйте новый каталог кэша:
существующий HTML-кэш используется повторно для воспроизводимой сборки.

Коммитятся JSON в `src/data/`, включая `law-sources.json` с заголовками снимков,
ссылками на изменяющие документы и навигацией по редакциям. HTML-кэш не коммитится.
Загрузка использует ограниченное число потоков, проверяет ответы и сохраняет
успешный ответ атомарно. Неполный кэш сборщик отклоняет.

Для исторических снимков передайте `--revisions /path/to/manifest.json`.
Манифест — JSON-массив записей:

- `doc`: `pdd`, `koap` или `uk`;
- `url`: URL **самого консолидированного документа выбранной редакции**;
- `revisionDate`: дата редакции из заголовка источника;
- `validFrom` и `validTo`: проверенный период действия, конец исключительно;
- `effectiveSource`: URL источника проверки периода действия.

Архивные снимки сохраняются в `<cache>/<doc>/<revisionDate>/`.
Дата в манифесте должна совпасть с заголовком. Сборщик объединяет снимки
по идентификаторам нормы и отклоняет конфликты и пересечения.
Задайте `validTo` каждого исторического снимка: сборщик не выводит автоматически
непрерывность истории из двух известных дат. Для частей с особыми сроками
вступления в силу потребуется отдельная юридическая проверка интервалов.

У КоАП и УК выбирайте снимки через список редакций КонсультантПлюс. Для ПДД
проверяйте сроки по постановлениям Правительства из `amendments` в
`law-sources.json`. Текст изменяющего постановления сам по себе не является
консолидированным текстом ПДД; подставлять его вместо ПДД нельзя.

Полная история редакций автоматически не восстановлена. При отсутствии
подтверждённого периода началом мигрированного интервала служит дата редакции
из заголовка источника (по правилу миграции), **не дата сборки JSON**. Такая
редакция содержит `legalCheck`: дата редакции документа не равна подтверждённой
дате вступления в силу каждой его нормы. Наличие редакции на сегодняшнюю дату
не означает юридическую проверку всех сроков или исторической полноты.
