Альтернатива: GPT-6.1 Sol high.

Репозиторий: https://github.com/dur0vd/Crashtest

Общая проверенная база: origin/codex/full-simulator-base-v2

Зависимости: Нет веток-зависимостей. Можно запускать одновременно с двумя другими чатами.

Последнее указание пользователя: всего четыре чата. Первые три работают
ОДНОВРЕМЕННО и НЕ ЗАВИСЯТ от результатов друг друга. Четвёртый запускается
после них для подключения, проверки и объединения. Это заменяет старые
23 промпта, очереди веток и запреты начинать 07.2 без отдельной ветки 06.6.
Старые blocking-handoff описывают прежнюю схему, а не обязательство ждать её.

В общей базе уже есть 04–05, 06.1–06.3 и проверенное объединение парковки,
велосипедистов/СИМ и пассажиров. Повторная проверка общего кода: 1115 тестов
в 35 файлах, npm run build успешно. Это не означает юридическую полноту
или натурную валидацию: открытые ограничения перечислены в
docs/STATUS-AUDIT-2026-10-22.md и исходных handoff.
Не реализовывай эти модули заново; исправляй только воспроизведённые пробелы
своей области. Ядро 07.1 (27cf511) уже включено: Dugoff/силы/подшаг/параметры.
Его не нужно писать заново. В 07.2/08.1 пока подготовка и блокировки; ядро
ещё не подключено к маршрутам/общему simulate(). Это не готовые динамика сцены и удар.

1. Сначала git status, git log, git worktree list. Сохрани чужую работу.
   Используй свою ветку и отдельный worktree/клон. Не меняй рабочую папку другого
   чата. Не делай reset/rebase/force-push, не меняй main и общую базу.
   Если своя ветка уже есть, продолжи её историю с настройкой tracking;
   команды создания ниже относятся только к первому запуску.
2. Прочитай AGENTS.md и docs/codex/README.md, если появились, затем

   docs/PARALLEL-CONTRACT.md и src/parallel/contracts.ts. Старые документы

3. Первые три чата не fetch/merge ветки друг друга для продолжения задачи.
   Работа идёт от общей базы с фиксированными границами. Для межмодульного

4. Сохраняй совместимость сцен, известное/неизвестное, даты редакций,

   Конкретный TODO(legal-check)/TODO(source-check) не заменяет остальную работу:

5. Работай по внутренним проверяемым подэтапам и продолжай в ЭТОМ же чате до
   завершения всей своей области. После каждого законченного подэтапа —
   npm test и npm run build, отдельный коммит и push своей ветки. Не заканчивай
   всю задачу после одного маленького подпункта. После прерывания продолжай
   по своему отчёту и реальному git diff, не переделывай уже готовое.
6. Проверки должны быть независимыми: аналитика/измеренные треки/опубликованный
   пример, а не копирование ожидаемого значения из реализации. Изменённый UI

7. Своя профильная документация и уникальный docs/handoffs/parallel-*.md:

   ограничения, файлы за пределами своей области и что подключить интегратору.
   Не переписывай чужие handoff и общий каталог. Не записывай SHA коммита

8. Общие файлы трогать только по таблице владельцев в PARALLEL-CONTRACT.md.

9. Публиковать только свою ветку. Первые три чата не сливают соседей;

ТВОЯ ЗАДАЧА

Твоя область — оставшаяся ГРАФИКА, ИНТЕРФЕЙС И РАБОТА С МАТЕРИАЛАМИ.
Это не косметическая смена цветов: нужны редактор/визуализации, evidence,
видео, отчёты, проекты, мобильный мастер и безопасное локальное хранение.
Весь существующий редактор и новые формы парковки/СИМ/пассажиров уже работают;
сохрани их и не реализуй заново. Новую физику и нормы не рассчитывай сам.

Владеешь src/workbench/**, src/evidence/**, src/media/**, src/reports/**,
src/project/**, src/privacy/**, src/cli/**, ui/editor/render/main/style,
index.html, package.json/lock и мобильной оболочкой. В Scene не добавляй
конкурирующие научные/правовые схемы: новые данные храни в ProjectEnvelope.
Экспорт: src/workbench/mount.ts → mountWorkbench(element, context),
context: { project: ProjectEnvelope, ports: WorkbenchPorts,
           onProjectChange(project: ProjectEnvelope): void };
результат { destroy(): void }. Контракт импортировать из общей базы.

Первые три чата работают одновременно. При отсутствии physics/rules порта
показывай «Расчёт недоступен в этой сборке», сохраняя ввод. Не импортируй
src/physics/port.ts или src/rules/port.ts до их появления и не жди эти ветки.
Общий UI должен работать с инъекцией WorkbenchPorts; четвёртый чат подключит
реальные factories. Тестовые двойники допустимы только для UI-тестов.
Сохранение/редактор/медиа/экспорт проверяй реальными файлами и браузером.

1. Формы по describe(project): физические параметры, t1–t3/j, диапазоны и
   источники, три состояния правовых фактов, передача в назначенное пространство.
   Редактор измеренных зон μ/уклона/неровностей. Воспроизведение динамического
   Timeline/renderData: колёса, векторы сил, снос/вращение/вторичные контакты,
   обзорность/опасность, шкалы и единицы. Не делать второй скрытый симулятор.
   Панель реконструкции: ограничения, прогресс/отмена, residual каждого evidence,
   распределения/гистограммы/tornado и доступ к численному trace.
2. Evidence: следы торможения/юза/заноса с колесом/ABS-прерывистостью/шириной,
   осыпь/жидкости/задиры, место удара с уверенностью и кем установлено,
   финальные позы ТС/тела, C1–C6, зафиксированные знаки/сигналы. У каждого
   источник, погрешность, комментарий. Два ориентира, растровая подложка по
   масштабу/прозрачность, оригинал фото/EXIF/хэш. Противоречия показывать,
   не менять наблюдения для совпадения с моделью. Масштабный PDF/SVG с легендой,
   размерами и пустыми подписями. OSM необязателен, с атрибуцией.
3. Видео локально: оригинал/SHA256, реальные PTS/кадры/VFR-предупреждение,
   покадровая навигация, разметка wheel-ground/4+точек и погрешностей,
   синхронизация светофора/Timeline и overlay. Численную гомографию/скорость
   запрашивать у PhysicsPort.calculate, не считать seek/FPS доказанным временем
   и не писать второй вычислительный движок. При недоступном расчёте сохранять
   истинные кадры/разметку, не показывать выдуманные скорости.
4. PDF с локальным лицензированным кириллическим шрифтом и DOCX: три шаблона
   (комиссар/специалист/учебный), запрос/автор/дата/вопросы, материалы/хэши,
   параметры/погрешности, методы/подстановки/промежуточные расчёты, графики,
   ответы каждому вопросу по calculation-ID, версия/хэш/журнал. technical,
   rules и legal раздельны; expert legal выключен по умолчанию. Нет слова
   «виновен» и вывода без основания. Правовую структуру согласовать с данными
   RulePort, не сочинять нормативные тексты. PDF реально открывается;
   snapshots текста для 3 пресетов, кириллица/хэш/отключение legal проверены.
5. Project .crashtest ZIP: канонический scene.json и extensions/evidence,
   оригинальные вложения как есть, SHA256 manifest payload (не самого manifest),
   версии engine/UI/corpus, сохранённые результаты/журнал. Точность чисел
   согласовать с входами, не терять значимые разряды; -0/нечисла/порядок ключей.
   Импорт: целостность, версии, миграции, пути/лимиты ZIP и старые сцены.
   Локальный журнал было/стало/кто/время, undo/redo и откат, камера не правка.
   Проверка воспроизводимости принимает порт, показывает diff/несовпадение
   версий. Кодек/канонизация/проверка ZIP работают без DOM.
6. CLI crashtest-verify: аргументы, чтение проекта, проверка целостности,
   вывод хэшей и результатов, коды ошибки/недоступного движка. Вычислительный
   порт передаётся в общий verifier; конечную инъекцию factories выполняет
   четвёртый чат. Не выдавать одну проверку ZIP за пересчёт. Добавь локальный
   bin и инструкцию npm exec/npx; npm-публикацию не делать.
7. Мобильный комиссар: дата/адрес/гео → шаблон → ТС/номера/ОСАГО → позиции →
   следы → tap-повреждения → фото/чек-лист ракурсов → текст/диктовка → разбор.
   Оригиналы/EXIF/время/геометка/хэш, измерения рулеткой с точностью,
   offline/автосохранение/экспорт, крупный светлый high-contrast UI/одна рука.
   Диктовка с честным текстовым fallback, без скрытой облачной отправки.
   Европротокол/правовые подсказки через RulesPort. AR необязателен.
   Проверить mobile browser и доступные Capacitor Android/iOS checks;
   отсутствие SDK описать, не выдавать за собранный нативный релиз.
8. Безопасность уже при появлении ПДн: IndexedDB/файлы, без внешней передачи;
   URL-share блокируется/обезличивается. AES-GCM с PBKDF2/Argon2 и случайными
   salt/nonce, tamper/wrong-password проверки. Redacted ZIP/отчёт исключает
   исходные фото/EXIF/номера/полисы/ПДн в журнале и старых состояниях;
   локальное ручное размытие лиц/номеров. Полное удаление проекта/вложений.
   CSP и фактический аудит сетевых запросов/allowlist, docs/PRIVACY.md по
   реальному поведению, правовые формулировки оставить с конкретным TODO.
9. Необязательный учебный режим 19 не блокирует обязательное: вопросы по
   действительному report без выдуманного ответа, каталог AB/сложность,
   проектор/паузы/уроки без ПДн, минимальный размер знаков, пять шаблонов
   Т/крест/кольцо/двор/трасса. Вид от водителя использует физическую обзорность,
   а не декоративную камеру с вымышленной видимостью.

Все функции UI и документов получают CalculationRecord/Report/Timeline как
данные. Проверяй их генерацию/редактирование независимо от соседних движков;
контрольные fixtures обозначай синтетическими. Полное приложение оживит
интегратор; готовность твоей области означает рабочие редакторы, реальные
форматы/файлы/хранилище и адаптеры, а не набор декоративных кнопок.
