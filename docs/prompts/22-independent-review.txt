Независимая проверка объединённого симулятора

Рекомендуемая модель: GPT-6 Astra high.
Альтернатива: Claude Opus 5.5.
Желательно, чтобы проверяющий не писал проверяемые формулы и их тесты.

ПРОМПТ

Репозиторий: https://github.com/dur0vd/Crashtest
Твоя ветка: codex/full-simulator-review
Отдельный worktree: ../Crashtest-worktrees/full-simulator-review
Проверяемая ветка по умолчанию: codex/full-simulator-integration.
Этот промпт запускается ПОСЛЕ 23. Если для отдельного этапа пользователь
явно указал иную ветку/SHA, проверить её, сохранив тот же режим отчёта.

Сначала проверить git status/log и git worktree list, сохранить чужую работу.
Получить проверяемую ветку обычным fetch, зафиксировать её SHA. Если её ещё
нет, сообщить о зависимости; не выбирать случайный коммит вместо объекта проверки.
Прочитать docs/prompts/branches.json, AGENTS.md и docs/codex/README.md,
если появились, затем исходный запрос, план, handoff и отчёт интеграции.

Первый запуск из отдельного клона или свободной папки репозитория:

git fetch origin refs/heads/codex/full-simulator-integration:refs/remotes/origin/codex/full-simulator-integration
git rev-parse origin/codex/full-simulator-integration
git worktree add -b codex/full-simulator-review ../Crashtest-worktrees/full-simulator-review origin/codex/full-simulator-integration
cd ../Crashtest-worktrees/full-simulator-review

Если ветка проверки уже существует, продолжить её в её worktree. Проверяемые
обновления подключать обычным merge только после фиксации нового reviewedSha.
Не пересоздавать ветку, не переписывать историю и не трогать рабочую папку автора.

Исходники и существующие тесты не менять. Проверять независимо: ложные правовые
выводы, неизвестность/источники, размерности/балансы, скрытый fallback,
недетерминизм, потерю оригиналов и утечки ПДн. Зелёный тест не доказывает
корректность, если ожидание повторяет реализацию. Использовать наблюдаемый
или аналитический пример, запускать доступные проверки из своего worktree.
Не объявлять нормативный/физический TODO закрытым без доказательства.

Записать только отчёт docs/reviews/full-simulator-review.md: reviewedSha,
область, команды/результаты, существенные находки с файлом/строкой,
воспроизведением, последствием и конкретным исправлением. Если находок нет,
перечислить проверенные сценарии и непроверенные ограничения.
Для воспроизведений использовать временные файлы вне исходного проекта.

Публикация: коммит «Проверка: независимый разбор объединённого симулятора»,
затем git push -u origin codex/full-simulator-review.
До коммита проверить, что diff содержит только свой отчёт.
Не сливать автоматически в integration/main. В финале дать SHA отчёта,
reviewedSha и итог проверки. Любые последующие изменения кода требуют
проверки актуальности найденного результата.
