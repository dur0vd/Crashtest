# Этапы анализа

`analyze(scene, timeline)` в `src/analysis.ts` последовательно вызывает три этапа.

1. `analysis/technical.ts` получает сцену и результат симуляции. Формирует точки траекторий (скорость, положение относительно оси и полос), пересечения стоп-линий с сигналом на момент пересечения, контакты, сближения, обгоны, оценки опасности и возможности остановиться. Юридических ссылок здесь нет. Остановочный путь: `S = v0 * (t1 + t2) + v0² / (2j)`. Диапазон использует время реакции 0,8–1,2 с при неизменных остальных параметрах; это анализ чувствительности.
2. `analysis/traffic-rules.ts` сопоставляет наблюдения с требованиями ПДД, знаков и разметки. Возвращает `rules.findings`, статусы участников в `rules.actors` и объяснения конфликтов. `compliance`: «выполнено», «не выполнено», «не определить». Положительный вывод относится к конкретному наблюдавшемуся требованию, а отсутствие выявленных нарушений не означает проверку всех пунктов ПДД. Правила установления причинной связи сохранены из задачи 01. `prevention` отдельно показывает результат расчёта предотвращения: `true` / `false` / `null` (нет достаточного расчёта); контрфактическая симуляция всей сцены не выполняется.
3. `analysis/legal.ts` получает сцену и результат проверки ПДД. Определяет субъект, возможные составы, поглощение, отягчающие обстоятельства и санкции. Не меняет технический результат или выводы ПДД. Возраст задаётся через `Actor.age`; ребёнок без указанного возраста не считается установленным субъектом КоАП. Для прежних сцен взрослый участник без возраста предполагается совершеннолетним; допущение записано в trace как `subject.ageAssumed`.

Все структурированные выводы содержат `trace`: входные данные, кадры, скорость, параметры дороги/сигналов, использованные пороги и промежуточные результаты. Техническая оценка остановки хранит, в частности, `v0`, `t1`, `t2`, `j`, `S`, `available`. Выводы ПДД включают наблюдения и оценки возможности предотвращения; правовые выводы — субъект, признаки, последствия, исходные нарушения и дату снимка норм.

`Report.technical`, `.rules`, `.legal` — основные разделы для UI и будущего отчёта. Прежние `findings`, `collisions`, `verdicts`, `duties`, `events` оставлены как представления для совместимости. Только совместимое `findings` содержит дополненные правовые ссылки; в `rules.findings` остаются ссылки на ПДД, знаки и разметку.

Статусы: `causal-violation`, `noncausal-violation`, `no-violations`, `insufficient-data`. Русские подписи централизованы в `STATUS_LABEL`.

## Даты и санкции

`Scene.env.accidentDate` задаёт местные дату и время ДТП. Правовой этап выбирает санкции через `lawRef(ref, date)` из датированного корпуса задачи 02, с источником и предупреждением о неподтверждённых сроках. Старое явно заданное поле `Scene.analysisDate` поддерживается как переопределение даты правовой оценки; отличие от даты ДТП записывается в предупреждения отчёта. При отсутствии подтверждённой редакции санкция возвращается как `null` с `available: false`. Нельзя выдавать сегодняшний текст за действовавший в прошлом или будущем. Квалификация остаётся ориентировочной.

Вспомогательный индекс `src/data/sanctions.json` (не источник санкций в отчёте) извлекается из имеющихся `koap.json` и `uk.json` командой `python tools/build-sanctions.py`. Обновление корпуса через `tools/build-law.py` также обновляет этот индекс. Полные тексты кодексов по-прежнему загружаются отдельно при обращении к справочнику.
